# L1 G0 接口

七步及公开内容唯一来源为相邻 `public/guide.{zh,en}.json`，JSON Schema 为本目录 `guide.schema.json`。L4 的 GuideStep 基础字段不变，逐层帮助放在其既有 `help: Record[]` 中：

| help.level | 字段 |
| --- | --- |
| direction | text、summary、source=authored_guidance、questions[{role,text}]、primary_action{id,label} |
| explanation | text |
| source | material_ids（授权原材料读取路径；company原文为新包brief末尾附录） |

`questions.role` 使用前端 manager/business/technical；只预填，不自动发送。primary_action.id 为 open_design/open_evaluation/open_submission；内容中的动作不是可任意执行的代码。STEP IDs 与 PRD 节键为 business/stakeholders/need/boundary/solution/assurance/decision。没有完成算法；由L4生成进度。

前端 `apps/web/src/aipm/host.ts` 是动作与UI挂载接口，`registry.ts` 提供空挂载口。L2/L3 的 installer 接收 host，通过 `host.registerFeature('design'|'evaluation', {render,mount})` 注册；render 仅返回本屏 HTML，mount 只操作分配 root，返回清理函数。`getDataHost` 用于已有读写；`getClient` 用L4客户端；`command` 由宿主记录原请求。泛型 TProgress/TClient 由消费方填L4类型，不在L1复制其DTO。

离线构建：在仓库根运行 `uv run --locked python scenarios/pm_pilot/aipm-phase1/build/build_candidate.py --output runs/254-evidence/<全新目录>`。`identity.json` 记录每语场景hash、原包hash、正式评价身份、缺失内容和加载结果。构建器要求新目录，不修改已安装包、不安装候选。公司状态仍 pending_user_confirmation。

为保留原场景历史测试记录的source窗口与引用跨度，公司一页纸追加到新候选的brief末尾；不新增助手知识域。原始跨度逐字节保留，唯一例外是英文候选：已发布英文brief写的是旧公司名 Xingqiao Digital，构建时统一替换为 Starbridge Digital，brief片段与来源为brief的事实跨度按替换长度平移并逐一校验。原测试记录字节不变，也没有将新附录冒称历史测试的输入。公开JSON仅由L4授权投影：冻结loader只允许材料原文出现在bundle.public_files，故aipm JSON在包内列private_files；其语义公开/私有分界另见aipm/manifest.json的路径。不能把private/grading送到前端。

正式评价版本仍feedback-rubric-v2-final.1，候选内容审批为not_recorded。新场景hash的识别资产/范围拟合未验证；由YH与192后续处理。生成成功不表示激活或语义质量已通过。
