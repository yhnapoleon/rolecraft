# RoleCraft 前端风格

**日期：** 2026-10-05

**对应实现：** `apps/web` 工作台 v4

**用途：** 改界面、加页面、做新岗位之前，先读这份文档。

这份文档分三层，约束力不同：

| 层 | 约束力 |
|---|---|
| **原则**（第 2 节） | 要守住。违背原则的设计再好看，也不是这个产品。 |
| **现在的做法**（第 3 节） | 是现有界面的真实参数，新东西默认沿用。有更好的做法时可以改，但要连同代码一起改，并更新这里。 |
| **留白**（第 4 节） | 刻意没定的地方，欢迎探索。 |

文档和代码不一致时，以代码为准，并尽快修正文档。

---

## 1. 气质

用户在这里接手一份真实的工作：有经理的委托、会变的政策、各有所知的同事、一个要决定能否上线的产品。界面像这间办公室里一张安静、可靠的工作台：世界在动，界面不吵。

几个词可以拿来校准：**安静、可信、有温度、有分量、诚实。**

- **安静：** 中性的画布，大量留白，颜色很少，只在有话要说时出现。
- **有温度：** 来自世界本身的东西：纸面上的衬线字、同事的头像和口吻、盖下去的章。不靠渐变和装饰色。
- **有分量：** 文档像纸，交付会盖章，条件是写着名字的数字。每样东西都能看出它在工作里是什么。
- **诚实：** 做不到的不假装能做，模拟的部分明确标出。

离这个气质最远的，是这几种样子：

- 一排排相同的圆角卡片；
- 仪表盘式的指标墙；
- 积分、徽章、进度条这类游戏化外壳；
- 系统旁白式的提示语；
- 为了好看而加的颜色和插图。

## 2. 原则

### 2.1 界面是世界里的工具

沉浸感的来源，是界面里的每样东西都属于这个工作世界。

- **用工作本身的语言说状态。** 例如写“政策 v2 / 索引 v1，索引落后”，不写“系统提示：数据可能过期”。
- **一个变化，在它影响到的每个地方都留下痕迹。** 政策更新后，会同时出现在这些地方：
  - 工作板的事件横幅；
  - 受影响的事项卡（“测试早于政策更新”）；
  - 资料卡的“有新版本”；
  - 测试台的索引状态；
  - 动态里的一条记录；
  - 同事的提醒。
- **后果可见，但不说教。** 反馈只写四件事：看到了什么、当时能知道什么、为什么重要、可以做什么。不打分，不说“你错了”，并且允许用户写“我有不同看法”。
- **人有身份、有边界。**
  - 同事用第一人称说话，只谈自己知道的事。
  - 用户自己的 Agent 是用户的工具，所以用和用户相同的颜色。
- **界面里不出现**：模型 ID、JSON、队列状态，以及“模拟”“训练”这类字眼。这些信息只放在“⋯ → 关于这个工作台”里。

### 2.2 诚实

- **后端做不到的，不在界面上假装。**
  - 前端规则生成的提醒和反馈，标“规则”或“规则示意”。
  - 演示用的样例，标“示例”。
  - 后端本地模式的回复，标“本地模式”。
  - 后端还没有英文版的内容，标 “Chinese source”。
- **分清两种保存状态。** “存在本机”和“已交给后端”，在界面上要看得出区别。
- **未知就说未知。** 证据不足，就显示为灰色的“还不知道”，不往好或坏的方向猜。

### 2.3 一种颜色只表达一种意思

| 颜色 | 意思 |
|---|---|
| 黑（墨色） | 你，以及你能做的事；你的 Agent 也用这个颜色 |
| 琥珀 | 外面变了，或者已经过期 |
| 绿 | 站得住：已完成、已满足、已批准、可用 |
| 红 | 超出了限制 |
| 灰 | 还不知道 |

**人物各有一个固定色相，只用在头像和标识上：** Priya 紫、Mei 洋红、Daniel 青、知识助手蓝。

**不用颜色表达的信息：**
- 优先级用柱形，3、2、1 格分别是先做、随后、暂放。
- 进展用圆形：空心是待处理，半圆是正在做，打勾是已处理。

**想加一个新颜色之前，先回答两个问题：** 它表达的是哪一类意思？现有的五类能不能表达？两个都答不上来，就不加。

### 2.4 用户随时知道自己在哪、从哪来、发生了什么

- **返回按层级走。** 事项、资料、测试台都回到工作板；只有在工作板上，才是“离开”。
- **每个动作都有落点。** 提示条只负责提醒，真正的记录要能在别处找到：
  - 这件事的目录；
  - 动态；
  - Agent 标签的“它做了什么”。
- **撤销跟着页面走。** 离开页面，撤销就收回。

### 2.5 字越少越好

- **能用位置、形状、头像说明的，就不写字。**
- **提示最多一句话。** 解释性的内容集中放到“关于”里。
- **文案要求：** 动词开头、口语、具体。按钮写清点了会发生什么，前后用同一个词：按钮叫“交付”，完成后就说“已交付”。
- **同事的话写成人话。** 规则生成的提醒也要像同事会说的话。

### 2.6 双语、深色、手机、无障碍是底线

- **文案中英成对写。** 一律写成 `T('中文', 'English')`。默认跟随系统语言，可以手动切换。
- **中英排版不同。** 中文不加字距；英文标题收紧字距。
- **五种情况都要看过：** 浅色、深色、桌面、390px 手机宽度、键盘操作。不能有横向滚动，也不能有被挤成竖排的文字。
- **焦点和动效：**
  - 焦点要看得见；
  - 遵守系统的“减少动态效果”设置；
  - 拖动操作要有键盘替代（看板支持 ⌥ + 方向键）。

## 3. 现在的做法

下面的参数取自 `apps/web/src/app/styles.css`。改动时以该文件为准。

### 3.1 色板

| 用途 | 变量 | 浅色 | 深色 |
|---|---|---|---|
| 画布 | `--canvas` | `#eceef2` | `#0e0f12` |
| 面板 | `--surface` | `#ffffff` | `#17191e` |
| 纸面 | `--paper` | `#ffffff` | `#1b1e23` |
| 墨色 | `--ink` | `#15171c` | `#f2f3f5` |
| 次级文字 | `--ink-2` / `--ink-3` / `--ink-4` | `#4b505b` / `#7b818d` / `#a9aeb7` | `#b4b9c2` / `#868c97` / `#5d636e` |
| 变了／过期 | `--warn` | `#b5530b` | `#f0a35b` |
| 站得住 | `--good` | `#16794a` | `#57c98c` |
| 超限 | `--bad` | `#c0392b` | `#f07a6e` |
| Priya | `--p-manager` | `#7457e8` | `#9b86ff` |
| Mei | `--p-business` | `#c2449f` | `#ec7ccb` |
| Daniel | `--p-technical` | `#0d9484` | `#2fc2ad` |
| 知识助手 | 标识渐变 | `#4c6bff → #2bb7d1` | 同左 |
| 我的 Agent | 标识渐变 | `#545a67 → #15171c` | `#767d8b → #3a3f4b` |

- **画布背景：** 中性的冷灰，上面叠三层很淡的径向光（`body::before`），像房间里的自然光。
- **状态色的用法：** 一律用浅底配深字（例如 `--warn-tint` 底配 `--warn` 字），不用大面积的饱和色块。

### 3.2 字体

- **界面字体：** 系统字体，英文 SF、中文苹方。正文 14px，行高 1.5。数字用等宽数字（tabular-nums）。
- **标题：** 字重 600，字号分档如下：

  | 档 | 字号 | 英文字距 |
  |---|---|---|
  | 首屏 display | 52px（中文 48px） | -0.03em |
  | 大标题 | 36px | -0.02em |
  | 页面标题 | 26px | -0.015em |
  | 区块标题 | 17px | — |

  中文标题一律不加负字距。
- **衬线字（Newsreader，中文回落到宋体）：** 只用在“来自世界的文字”上：
  - 资料正文：17px，行高 1.7；
  - 资料标题；
  - 经理委托的引语；
  - 交付稿；
  - 变化情境里的引语。

  分工是：**衬线是世界里的人和文件在说话，无衬线是工具在说话。** 不要拿衬线做装饰。
- **行宽：** 长文不超过 72 个字符宽（72ch）。

### 3.3 形状与层次

- **圆角：** 一共五档，6 / 9 / 12 / 16 / 22px。
  - 按钮和标签：胶囊形。
  - 纸面：14px。
  - 大面板（测试台、事件横幅）：18px。
- **层次：** 靠阴影和留白分层，不用边框。阴影只有三档：
  - `--shadow-paper`：纸面；
  - `--shadow-card`：卡片；
  - `--shadow-float`：悬浮层和悬停状态。

  细分隔线只用在列表内部。
- **物件感：** 工作里本来就有的东西，可以做成物件：
  - 纸：资料、作品编辑器、交付稿；
  - 便签：同事的旁注；
  - 印章：已提交；
  - 写着名字的数字：条件卡，条件改变后显示原值。

  已经撤回的做法：情境封面图。它好看，但不表达任何信息。

### 3.4 布局

- **整体：** 顶部工具栏 56px，右栏 368px。宽度不够时，右栏收成抽屉。
- **工作板，从上到下：**
  1. 委托与条件；
  2. 世界事件；
  3. 知识助手；
  4. 事项看板；
  5. 资料。
- **事项工作台：** 左边目录，中间对象，底部动作条。
- **宽度断点：** 1279、1100、860、720px。到手机宽度时，横向排列的元素折行，不压缩正文。

### 3.5 动效

只在两种时候动：回应用户的操作，或者表现世界里的变化。现有的动效：

- **进入工作区：** 只编排这一次。三件起始事项从入口页移到看板上的位置，随后其余卡片和同事依次落下。
- **页面切换：** 用 View Transitions；重排看板卡片时用位置补间（FLIP）。
- **小反馈：**
  - 交付时盖章；
  - 同事“正在输入”时，头像外圈呼吸；
  - 获批的条件亮一下。

动效参数：

| 项 | 取值 |
|---|---|
| 主曲线 | 弹簧曲线 `--spring`，用 `linear()` 定义 |
| 备用曲线 | `cubic-bezier(.32, .72, 0, 1)` |
| 时长 | 160 / 280 / 520ms 三档 |
| 普通提示停留 | 3.2 秒 |
| 可撤销提示停留 | 6.5 秒 |

用户开启“减少动态效果”时，跳过这些动效，直接显示结果。

### 3.6 组件

| 组件 | 要点 |
|---|---|
| 条件卡 | 大数字加小名称。条件被外部改变时（如变化情境）用琥珀色，获批改变时用绿色，两种都写出原值；获批那一刻亮一下 |
| 世界事件横幅 | 琥珀色；写清发生了什么、影响什么；三个动作：看哪里变了、记为事项、知道了 |
| 看板卡 | 前面一个进展圆形，然后是标题；最新作品和用途、作品数和测试数；有提醒的同事头像；琥珀色标签只用于“过期”这类状态 |
| 资料卡 | 版本号、未读点、有新版本；“可以问”的同事头像，表示谁也有这份资料 |
| 纸面编辑器 | 用途标签只用图形区分：烧瓶是测试计划，分叉是方案比较，印章是试点决定；旁边是同事的便签 |
| 测试台 | 知识助手的配置和索引状态放在最上面；回答下方列出依据的版本 |
| 右栏 | 四个标签：讨论、反馈、Agent、动态；在事项里可以切换“这件事 / 整件工作” |
| 反馈观察 | 看到、当时可知、为什么重要、可以做什么、我有不同看法 |
| 提示条和弹层 | 提示条一句话，最多带一个动作；弹层用于设置、申请、交付这类需要专注的事 |

### 3.7 文案

| 不这样写 | 这样写 |
|---|---|
| 系统检测到索引可能已过期，请及时处理 | 政策 v2 / 索引 v1，索引落后 |
| 请点击下方按钮开始您的任务 | 开始写 |
| 恭喜完成！得分 85 | 已交付（盖章） |
| AI 建议您优先处理事项 A | Daniel：政策会变，索引会滞后，先测政策问答 |

## 4. 留白

下面这些方向是刻意没有定死的。去探索时，仍然要守住第 2 节的原则。

- **新岗位的物件：** 工程师岗位可以有自己的工作物件，例如终端、代码差异、测试报告，长相不必照搬产品经理的工作台。但颜色的含义、诚实标注、返回方式不变。
- **环境光与情境：** v3 试过让每个情境有自己的颜色，因为看不出含义而撤回。如果以后能找到真正表达含义的做法，可以再试，比如用光线表示“临近上线”。
- **空状态与插图：** 现在的空状态很朴素。可以做得更好，但必须是这个工作世界里的东西，不放泛用插画。
- **数据的呈现：** 测试结果对比、版本差异、评审结论，还有更好的可视化空间。图表同样遵守“一种颜色一个意思”。
- **时间感：** 可以在叙事上出现“第几天”，但不做真实倒计时。
- **更多质感：** 声音、触感，以及更细的物件细节（纸张、便签、印章），都可以试。标准是：去掉它，用户会觉得少了点什么；加上它，用户不会被打扰。

## 5. 为什么是现在这样

这些都是 2026-10-05 用户评审后做出的修正，留作判断依据：

| 之前的问题 | 现在的做法 |
|---|---|
| 灰白单调 | 用纸面、衬线、人物色和物件感加温度，不加装饰色 |
| 情境封面蓝、橙、绿好看，但看不出含义 | 删除；条件改用写着名字的数字 |
| 接手任务后只有一组磁贴，没有工作台 | 改为工作板加事项工作台两层 |
| 橙色、蓝色一色多义 | 一种颜色只表达一种意思；优先级和进展改用形状 |
| 点左上角岗位名直接退回首页 | 返回按层级走 |
| 反馈、测试、Agent 的产出不知道去了哪里 | 右栏四个标签加动态；Agent 标签显示它做了什么 |

## 6. 自检

改完界面后，问自己这几个问题：

1. 这个颜色表达的是哪一类意思？
2. 删掉这行字，用户还看得懂吗？
3. 这个变化在世界里留下痕迹了吗？用户回头能找到吗？
4. 这件事后端真的做得到吗？做不到的话，标出来了吗？
5. 它像一个真实的同事或工具会做的事吗？
6. 中英文、深色模式、手机宽度、键盘操作都看过了吗？
