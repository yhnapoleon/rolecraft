## 1. 气质

用户在这里接手一份真实的工作：有经理的委托、会变的政策、各有所知的同事、一个要决定能否上线的产品。界面像这间办公室里一张安静、可靠的工作台：世界在动，界面不吵。

几个词可以拿来校准：**安静、可信、有温度、有分量、诚实。**

- **安静：** 暖石色的桌面在一盏暖光下，大量留白，颜色很少，只在有话要说时出现。
- **有温度：** 来自世界本身的东西：纸面上的衬线字、同事的头像和口吻、盖下去的章。不靠装饰色。渐变只有一种用法，就是房间的光：桌面常驻一层暖光（窗口在上方）；政策刚变时这层光变亮。交付的绿色只在刻度、带子和印章上，不铺满桌面。
- **材质：** 桌面、实色仪器面、不透明纸、半透明材质构成四级层次。材质只用于框住窗口的工具栏和右栏，以及浮在内容上的菜单、弹层页脚和提示；桌上的产品条、看板槽位、连接台不玻璃化。
- **有分量：** 文档像纸，交付会盖章，条件是写着名字的数字。每样东西都能看出它在工作里是什么。
- **诚实：** 做不到的不假装能做，模拟的部分明确标出。

离这个气质最远的，是这几种样子：

- 一排排相同的圆角卡片；
- 仪表盘式的指标墙；
- 积分、徽章、进度条这类游戏化外壳（交付前预演卡的项数条是唯一例外，见 3.6）；
- 系统旁白式的提示语；
- 为了好看而加的颜色和插图。

## 2. 原则

### 2.1 界面是世界里的工具

沉浸感的来源，是界面里的每样东西都属于这个工作世界。

- **用工作本身的语言说状态。** 例如写“政策 v2 / 索引 v1，索引落后”，不写“系统提示：数据可能过期”。
- **一个变化，在它影响到的每个地方都留下痕迹。** 政策更新后，会同时出现在这些地方：
  - 工作板的事件横幅；
  - 受影响的事项卡（“测试早于政策更新”）；
  - 资料卡的“有新版本”；
  - 测试台的索引状态；
  - 动态里的一条记录；
  - 同事的提醒。
- **后果可见，但不说教。** 反馈只写四件事：看到了什么、当时能知道什么、为什么重要、可以做什么。不打分，不说“你错了”，并且允许用户写“我有不同看法”。
- **人有身份、有边界。**
  - 同事用第一人称说话，只谈自己知道的事。
  - 用户自己的 Agent 是用户的工具，所以用和用户相同的颜色。
- **界面里不出现**：模型 ID、JSON、队列状态，以及“模拟”“训练”这类字眼。这些信息只放在“⋯ → 关于这个工作台”里。
  - 模型身份（评价模型、注册模型 ID、修订、训练数据、权重阶段、融合成员）只在“⋯ → 关于这个工作台”里，反馈页不再写（2026-10-24，195 并入 190 经 189 的建议）。合成登记那块仍整块标“合成机制演示”，依据是用户 2026-10-12 的确认。
  - 系统剖面页（`#/lab`）是评审视角的页面，不在学员的工作流里：可以写方法名（XLM-R、BM25、e5、HMM 等）、实验编号、指标与“训练”“微调”，但仍不写识别器的注册 ID、版本哈希、证据 ID 和 JSON 原文。
  - 识别透镜（“⋯ → 识别透镜”，默认关）打开时，可以写识别方法名、课程类别和识别器的中间结果，用来在同一界面显出识别过程；置信度仍用短条表示，不写小数。透镜关着时，识别层只留下学员用得上的事实（例如“和上一次相比，回答里的数字从 500 变成 400”），多数位置什么也不显示。评审写进说明开头的“[识别一致]”这类标记一律不当正文显示。

### 2026-10-26：正常工作中的技术显化（262）

本轮授权补充上述透镜边界：批改单、结果页与「核对本版」的句子展开共用判断链，白话先行，方法名作辅注；真实的编码器、堆叠、规则、融合概率及代价可以显示数值。缺失分支不补画，检索方法未透出时如实说明，不从分数猜算法。识别透镜保留完整细节。桌面展开批改单句子时，原稿纸扩为整行，让判断链从左到右可读；窄容器与手机改为竖排。

结果页正常提供「回看工作过程」，同一次行为响应中的动作、阶段、参考与差异一起展示。参考是预设轨迹；并列最近明确说明。没有逐点 DTW 路径时不画对齐连线，动作带各保留自身顺序。阶段沿用中性深浅与纹理，避免借用业务语义色。

同事回复后的相关动作以轻量药丸呈现：已保存意图达到 0.70 的保守界面门槛，才对求批准／资源提供本人申请入口；流程动作只打开本回复确切引用的申请流程资料。门槛只是展示策略，未经校准，不表示模型可靠性保证。动作不预填、发送或批准。

### 2.2 诚实

- **后端做不到的，不在界面上假装。**
  - 前端规则生成的提醒和反馈，标“规则”或“规则示意”。
  - 演示用的样例，标“示例”。
  - 后端本地模式的回复，标“本地模式”。模型没接入的部分只在两处说：工作台顶栏一个模型状态标识（“模型：本地模式／部分接入／已接入”，点开逐项写哪部分等模型、现在用什么代替），以及条目旁一个灰色虚线小圈（读屏名“等待模型接入”，悬停一句说明）。条目上不再重复写“等待模型接入”这几个字，具体说明放进各自的详情（展开原文、成立条件与依据、模型建议的展开部分）。
  - 后端还没有英文版的内容，标 “Chinese source”。
- **分清两种保存状态。** “存在本机”和“已交给后端”，在界面上要看得出区别。
- **未知就说未知。** 证据不足，就显示为灰色的“还不知道”，不往好或坏的方向猜。

### 2.3 一种颜色只表达一种意思

| 颜色 | 意思 |
|---|---|
| 黑（墨色） | 你，以及你能做的事；你的 Agent 也用这个颜色 |
| 琥珀 | 外面变了，或者已经过期 |
| 绿 | 站得住：已完成、已满足、已批准、可用 |
| 红 | 超出了限制；同事入口的小红点专指未读消息（2026-10-25 用户指定） |
| 灰 | 还不知道 |

**人物各有一个固定色相，只用在头像和标识上：** Grace（经理）紫、Chen（业务负责人）洋红、Daniel（技术负责人）青、知识助手蓝。三位同事中英界面同名；称呼时只写名字（“问 Grace”“Chen 回复了你”），列出同事时写“名字（角色）”（英文 “Grace (manager)”），标题处名字旁小字写角色；名字只从 `apps/web/src/app/people.js` 取。资料原文里的称呼（如“陈敏”“经理”）按原文显示。中文里名字与汉字之间留一个空格。

**不用颜色表达的信息：**
- 优先级用柱形，3、2、1 格分别是先做、随后、暂放。
- 进展用圆形：空心是待处理，半圆是正在做，打勾是已处理。

**控件不借苹果蓝和绿色开关。** 主键用墨色；开关开启轨道浅色用墨色，深色按 209 稿用专用暖灰 `#8c857b`，绿继续只表示站得住、已完成。图标用 Lucide（ISC），不自托管 SF Pro 或 SF Symbols。

**想加一个新颜色之前，先回答两个问题：** 它表达的是哪一类意思？现有的五类能不能表达？两个都答不上来，就不加。

### 2.4 用户随时知道自己在哪、从哪来、发生了什么

- **同一顶帽子里按层级返回，换帽子用顶栏。** 产品经理帽子下，事项、资料、测试台都回到工作板，只有在工作板上才是“离开”。工程师帽子下，签字台和工作板一样是这顶帽子的首屏，不放返回键，回首页用顶栏左端的字标；复核报告屏的返回键由外壳画，回签字台。签字台不提供回产品经理工作板的返回键，换到产品经理用顶栏的帽子切换。
- **每个动作都有落点。** 提示条只负责提醒，真正的记录要能在别处找到：
  - 这件事的目录；
  - 动态；
  - Agent 标签的“它做了什么”。
- **撤销跟着页面走。** 离开页面，撤销就收回。

### 2.5 字越少越好

- **能用位置、形状、头像说明的，就不写字。**
- **提示最多一句话。** 解释性的内容集中放到“关于”里。
- **文案要求：** 动词开头、口语、具体。按钮写清点了会发生什么，前后用同一个词：按钮叫“交付”，完成后就说“已交付”。
- **同事的话写成人话。** 规则生成的提醒也要像同事会说的话。

### 2.6 双语、深色、手机、无障碍是底线

- **文案中英成对写。** 一律写成 `T('中文', 'English')`。默认跟随系统语言，可以手动切换。
- **中英排版不同。** 中文不加字距；英文标题收紧字距。
- **五种情况都要看过：** 浅色、深色、桌面、390px 手机宽度、键盘操作。不能有横向滚动，也不能有被挤成竖排的文字。
- **焦点和动效：**
  - 焦点要看得见；
  - 遵守系统的“减少动态效果”设置；
  - 拖动操作要有键盘替代（看板支持 ⌥ + 方向键）。

## 3. 现在的做法

下面的参数取自 `apps/web/src/app/styles.css`（颜色、字体、动效变量）和 `apps/web/src/app/material.css`（形状、表面、世界光）。改动时以这两个文件为准。

### 3.1 色板

| 用途 | 变量 | 浅色 | 深色 |
|---|---|---|---|
| 桌面（画布） | `--canvas` | `#ebe6dd`（暖石色） | `#13110e`（暖石墨） |
| 仪器面（桌上的面板） | `--surface` / `--surface-2` | `#f5f2ec` / `#ece7df` | `#1a1714` / `#221e1a` |
| 槽位（看板列） | `--surface-3` | `#e1dbd0` | `#0d0b09` |
| 纸面 | `--paper` | `#fffdf9`（暖白） | `#26221e` |
| 墨色 | `--ink` | `#1d1d1f` | `#f3f1ee` |
| 文字层级／装饰 | `--ink-2` / `--ink-3` / `--ink-4` | 同墨色 80% / 72% / 38% | 同墨色 78% / 62% / 32% |
| 细线 | `--line` / `--line-2` | `rgba(29, 29, 31, 0.10)` / `0.16` | `rgba(255, 248, 236, .08)` / `.14` |
| 变了／过期 | `--warn` | `#763d04`（在桌面最暖处仍过 4.5:1） | `#e7a15a` |
| 站得住 | `--good` | `#1b7149` | `#5bc28e` |
| 超限 | `--bad` | `#b3372a` | `#ee7a6a` |
| Grace（经理） | `--p-manager` | `#6550d0` | `#a08fff` |
| Chen（业务负责人） | `--p-business` | `#ad3f88` | `#ea7fc6` |
| Daniel（技术负责人） | `--p-technical` | `#0e7e70` | `#3cc2ae` |
| 知识助手 | 标识渐变 | `#4c6bff → #2bb7d1` | 同左 |
| 我的 Agent | 标识渐变 | `#4a5451 → #111715` | `#7d8885 → #343b39` |
| 环境光 | `--amb-a` / `--amb-b` / `--amb-c` | 琥珀 20% / 18% / 10% | 琥珀 10% / 8% / 5% |
| 桌面光 | `--light-calm` / `--light-warn` | 琥珀 16% / 22% | 琥珀 8% / 18% |
| 颗粒 | `--grain` | 3% 的拉伸噪点，只在光层上，盖不到纸 | 同左 |

- **深色对比度修正（2026-10-25，192 决定）：** 三级墨由 58% 提到 62%，保证最亮暖光区也达到 4.5:1；这是对 209 对比稿的明确修正，浅色不变。
- **文字：** `--ink-4` 仅装饰和禁用；可读文字使用 `--ink-3` 或更深层级。“还不知道”的计数随 `--ink-3`，不再使用旧灰绿。
- **控件底：** 次键浅色 `#fffefb`／深色 `#2c2824`；滑块浅色 `#fffefb`／深色 `#3a352f`。主键使用墨色，浅色配 `#fbfaf8` 字，深色配 `#1a1714` 字。
- **明度台阶：** 槽位 < 桌面 < 仪器面 < 纸。仪器面不描边、不投影，只比桌面亮一档；纸保留独立纸影；材质用顶边高光和浮层投影。
- **光：** 整个房间常驻一层暖光（`body::before` 的三处 `--amb-*`：左上、右上、右下一点反光），首页、工作板、My agent、结果页、签字台都一样。主屏顶上 560px 另有一池稳定的暖光（`--light-calm`）；工作板上出现世界事件时，叠上一层更亮的（`--light-warn`），用透明度淡入。交付和结果都不换成绿光：绿色只在刻度、已交付带子和印章上；交付以后，板上剩下的事件也不再让光变亮。光层上叠一层 3% 的颗粒（`--grain`），防止大面积渐变出现一圈圈色带。光只淡入，不动。做法在 `apps/web/src/app/material.css`。
- **状态色的用法：** 一律用浅底配深字（例如 `--warn-tint` 底配 `--warn` 字），不用大面积的饱和色块。

**半透明材质（第二步 B）：**

| 表面 | 浅色 | 深色 | 模糊 |
| --- | --- | --- | --- |
| 工具栏 | `rgba(245,242,236,.60)` | `rgba(26,23,20,.60)` | 24px，饱和度 170% / 150% |
| 桌面右栏 | `rgba(245,242,236,.50)` | `rgba(26,23,20,.50)` | 无；里面的同事便签仍是纸 |
| 手机右栏抽屉 | 同色 .90 | 同色 .90 | 无；覆盖正文时提高遮蔽，确保文字 ≥4.5:1 |
| 菜单、popover、toast | `rgba(250,247,242,.72)` | `rgba(44,40,35,.68)` | 30px，饱和度 180% / 150%；顶边高光 .70 / .09 |
| 资料与对话框页脚 | 纸色 62% | 纸色 62% | 20px，饱和度 170% |

默认变量为实色 `--surface`、无模糊；支持标准或 WebKit `backdrop-filter` 才启用材质。减少透明度时恢复实色并去掉模糊，深色覆盖规则与普通深色变量具有相同权重。减少动态效果继续沿用原规则。

滤镜声明先写 WebKit 前缀、后写标准属性，生产构建必须保留标准属性；已用实际计算样式核对，不能只看源码声明。

工具栏的滤镜放在独立 `::before` 背景层，避免父滤镜截断菜单对其后内容的取样；菜单仍在原位置、行为不变。首页顶端背景透明，滚动后背景层出现。工作台滚动容器 `.stage` 在工具栏下方且裁剪溢出，内部光池保持原位；工具栏透出已有全局环境光，没有把光池强行移出滚动区。

资料正文和页脚占同一网格行，页脚贴底覆盖，正文能滚到材质下；底部保留 110px 滚动余量，末段可滚到页脚上方。菜单项目选中用墨底与反色字。

### 3.2 字体

- **界面字体：** Instrument Sans（可变宽度与字重），中文回落苹方。字体文件随应用打包（`@fontsource-variable/instrument-sans`，SIL OFL 1.1），演示不联网也能用。正文 14px，行高 1.5。数字用等宽数字（tabular-nums）。
- **等宽字：** 只用于代码标识符：配置键名（`freshness_guard`，只出现在工程师签字台）、探针编号（F01）、哈希前缀。计数、读数与时间（“公开 4/4 通过”“1/1 与记录一致”“60/500”“18:36”）不用等宽字，用 Instrument Sans 的等宽数字（`font-variant-numeric: tabular-nums`）。
- **读数：** 条件读数的数字用 Instrument Sans 78% 窄体，44px（手机 34px），字重 500；单位用 13px 正文字跟在旁边。知识助手面板的读数是 14px 粗体，名称 11.5px 在上。
- **标题：** 字重 600，字号分档如下：

  | 档 | 字号 | 英文字距 |
  |---|---|---|
  | 首屏 display | 52px（中文 48px） | -0.03em |
  | 大标题 | 36px | -0.02em |
  | 页面标题 | 26px | -0.015em |
  | 区块标题 | 17px | — |

  中文标题一律不加负字距。
- **衬线字（Newsreader，随应用打包，SIL OFL 1.1；中文回落到宋体）：** 只用在“来自世界的文字”上：
  - 资料正文：17px，行高 1.7；
  - 资料标题；
  - 经理委托的引语；
  - 交付稿；
  - 变化情境里的引语。

  分工是：**衬线是世界里的人和文件在说话，无衬线是工具在说话。** 不要拿衬线做装饰。
- **行宽：** 长文不超过 72 个字符宽（72ch）。

### 3.3 形状与层次

- **世界事件：** 事件出现时，顶边的琥珀线从左往右画一次（520ms，`--ease-out` 即 `cubic-bezier(.23, 1, .32, 1)`），世界光同时淡入；减少动态效果时直接显示。
- **小反馈：**
  - 交付时盖章（见 3.6“交付盖章”）；
  - 同事“正在输入”时，头像外圈呼吸；
  - 获批的条件亮一下。

- **顶栏（2026-10-24 第二轮重设计）：**
  - 帽子切换：白色滑块在两项之间滑动，200ms 弹簧（复制一层文字按 clip-path 裁到选中项、阴影放在外层，滑动中文字颜色始终正确）；滑块先动，约 120ms 后主屏才换；准备另一顶帽子的屏时旁边一个旋转点，失败立刻滑回并用提示条说原因；

  - 主键换字：旧字以 `blur(2px)` 淡出、新字淡入（160ms），键宽用 FLIP 跟上（280ms）；
  - Agent 灯：平时静止；每次真实调用，外圈放大到 2.2 倍同时淡出，520ms，一次，不循环。
- **按键：** 按下 `scale(.97)` 160ms；悬停只在能悬停的设备上生效（`@media (hover: hover) and (pointer: fine)`）；完成时图标经 `blur(2px)` 交叉过渡成对勾，1.6 秒后复原。

| 复核报告屏（`#/engineer-review/<复核>`） | 返回键由外壳画，回签字台。头部同签字台，加几枚事实（第 n 次复核、时刻、这次复核之后还剩 n 次；草稿来自 Agent 时加“草稿来自你的 Agent”）和下一步动作排头：墨色主键在顶栏（签字台读过时）；直接刷新进报告、顶栏还没有主键时，报告自己的键才用墨色。全部站得住（目标修好、公开与隐藏都没有新增失败、比较完整）时主键是“回到产品经理工作板”，“再修一轮”降为次级键；其余情况主键是“再修一轮”（回签字台，候选设置原样还在）。正文是会话 190 的回归报告组件（见上一行），检索说明写“规则版检索”。同一委托有两次以上复核时，下面列出各次（当前一次标“正在看”）。没有“发回产品经理” |
| 交给工程 | 测试台工具区一个幽灵键（有测试、且情境装了工程回归探针时才出现）。弹层“交给工程”（打开时焦点在标题，复选框不先套焦点环）：一句“选要修的测试，引用过期版本的已经选上。”，逐条复选（问题、琥珀“引用的版本已经过期”、回答摘要一行）；最多 10 条，选满后其余变灰并写“已选满 10 条；要换一条，先取消一条。”。主键写数量“交给工程（n 条）”，开委托后直接进签字台 |

## 4. 留白

下面这些方向是刻意没有定死的。去探索时，仍然要守住第 2 节的原则。

- **新岗位的物件：** 工程师岗位可以有自己的工作物件，例如终端、代码差异、测试报告，长相不必照搬产品经理的工作台。但颜色的含义、诚实标注、返回方式不变。
- **环境光与情境：** v3 试过让每个情境有自己的颜色，因为看不出含义而撤回。如果以后能找到真正表达含义的做法，可以再试，比如用光线表示“临近上线”。
- **空状态与插图：** 现在的空状态很朴素。可以做得更好，但必须是这个工作世界里的东西，不放泛用插画。
- **数据的呈现：** 测试结果对比、版本差异、评审结论，还有更好的可视化空间。图表同样遵守“一种颜色一个意思”。
- **时间感：** 可以在叙事上出现“第几天”，但不做真实倒计时。
- **更多质感：** 声音、触感，以及更细的物件细节（纸张、便签、印章），都可以试。标准是：去掉它，用户会觉得少了点什么；加上它，用户不会被打扰。

## 5. 为什么是现在这样

这些都是用户评审后做出的修正（2026-10-05，最后几行是 2026-10-24），留作判断依据：

| 之前的问题 | 现在的做法 |
|---|---|
| 灰白单调 | 用纸面、衬线、人物色和物件感加温度，不加装饰色 |
| 情境封面蓝、橙、绿好看，但看不出含义 | 删除；条件改用写着名字的数字 |
| 接手任务后只有一组磁贴，没有工作台 | 改为工作板加事项工作台两层 |
| 橙色、蓝色一色多义 | 一种颜色只表达一种意思；优先级和进展改用形状 |
| 点左上角岗位名直接退回首页 | 返回按层级走 |
| 反馈、测试、Agent 的产出不知道去了哪里 | 右栏四个标签加动态；Agent 标签显示它做了什么 |
| 灰白卡片墙：每块内容都是同一种圆角白卡（2026-10-24） | 「仪器与纸」：桌面是仪器，世界送来的是纸；层次靠明度台阶和细线，只有纸浮起来；桌面在一层常驻暖光下（2026-10-24 用户看过预览二后改定：原先只有世界变化时才有光，平时灰绿、交付后满屏淡绿，显得单薄单一） |
| 回归报告修一个、坏一个时头图只有绿勾，新增失败藏在下面的计数里（2026-10-24，197） | 新增失败大于 0 时头图换琥珀 ↓，标题写“目标修好了，但新增 1 处失败”，下面两行各带记号 |
| 字段名、计数和时间都用等宽字，分不出哪些是要复制的名字（2026-10-24，197） | 等宽字只给代码标识符；字段名只在签字台、点一下整段选中；计数读数用等宽数字 |
| 吸顶顶栏盖住跳转到的标题（2026-10-24，197） | 跳转目标加 `scroll-margin-top: calc(var(--toolbar-h) + 16px)` |

## 6. 自检

改完界面后，问自己这几个问题：

1. 这个颜色表达的是哪一类意思？
2. 删掉这行字，用户还看得懂吗？
3. 这个变化在世界里留下痕迹了吗？用户回头能找到吗？
4. 这件事后端真的做得到吗？做不到的话，标出来了吗？
5. 它像一个真实的同事或工具会做的事吗？
6. 中英文、深色模式、手机宽度、键盘操作都看过了吗？
