# RoleCraft 前端风格

**日期：** 2026-10-05；2026-10-24 改为「仪器与纸」材质，同日加工程师岗位（签字台，见 3.6）

**对应实现：** `apps/web` 工作台 v4

**用途：** 改界面、加页面、做新岗位之前，先读这份文档。

这份文档分三层，约束力不同：

| 层 | 约束力 |
|---|---|
| **原则**（第 2 节） | 要守住。违背原则的设计再好看，也不是这个产品。 |
| **现在的做法**（第 3 节） | 是现有界面的真实参数，新东西默认沿用。有更好的做法时可以改，但要连同代码一起改，并更新这里。 |

文档和代码不一致时，以代码为准，并尽快修正文档。

## 1. 气质

用户在这里接手一份真实的工作：有经理的委托、会变的政策、各有所知的同事、一个要决定能否上线的产品。界面像这间办公室里一张安静、可靠的工作台：世界在动，界面不吵。

几个词可以拿来校准：**安静、可信、有温度、有分量、诚实。**

- **安静：** 矿物灰绿的桌面，大量留白，颜色很少，只在有话要说时出现。
- **有温度：** 来自世界本身的东西：纸面上的衬线字、同事的头像和口吻、盖下去的章。不靠装饰色。渐变只有一种用法，就是世界状态的光：政策刚变时，桌面顶上透出琥珀光；刚交付时是绿光；其余时候没有光。
- **材质：** 桌面是一台校准过的仪器，世界送来的东西都是纸。层次靠明度台阶，从低到高是槽位、桌面、仪器面、纸，不靠卡片。区域之间用细线分开，只有纸浮起来。
- **有分量：** 文档像纸，交付会盖章，条件是写着名字的数字。每样东西都能看出它在工作里是什么。
- **诚实：** 做不到的不假装能做，模拟的部分明确标出。

离这个气质最远的，是这几种样子：

- 一排排相同的圆角卡片；
- 仪表盘式的指标墙；
- 积分、徽章、进度条这类游戏化外壳（交付前预演卡的项数条是唯一例外，见 3.6）；
- 系统旁白式的提示语；
- 为了好看而加的颜色和插图。

## 2. 原则

### 2.1 界面是世界里的工具

沉浸感的来源，是界面里的每样东西都属于这个工作世界。

- **用工作本身的语言说状态。** 例如写“政策 v2 / 索引 v1，索引落后”，不写“系统提示：数据可能过期”。
- **一个变化，在它影响到的每个地方都留下痕迹。** 政策更新后，会同时出现在这些地方：
  - 工作板的事件横幅；
  - 受影响的事项卡（“测试早于政策更新”）；
  - 资料卡的“有新版本”；
  - 测试台的索引状态；
  - 动态里的一条记录；
  - 同事的提醒。
- **后果可见，但不说教。** 反馈只写四件事：看到了什么、当时能知道什么、为什么重要、可以做什么。不打分，不说“你错了”，并且允许用户写“我有不同看法”。
- **人有身份、有边界。**
  - 同事用第一人称说话，只谈自己知道的事。
  - 用户自己的 Agent 是用户的工具，所以用和用户相同的颜色。
- **界面里不出现**：模型 ID、JSON、队列状态，以及“模拟”“训练”这类字眼。这些信息只放在“⋯ → 关于这个工作台”里。
  - 唯一例外是反馈页“理由与证据的支持关系”下的模型建议块：评价模型行、注册身份与“训练数据”等行可以写模型 ID、版本和“训练”。依据是用户 2026-10-12 确认的“合成登记在界面显示标签与证据，整块标合成机制演示”，以及模型承接波任务书 §3.6 对模型身份显示的要求。其他界面照旧。
  - 系统剖面页（`#/lab`）是评审视角的页面，不在学员的工作流里：可以写方法名（XLM-R、BM25、e5、HMM 等）、实验编号、指标与“训练”“微调”，但仍不写识别器的注册 ID、版本哈希、证据 ID 和 JSON 原文。
  - 识别透镜（“⋯ → 识别透镜”，默认关）打开时，可以写识别方法名、课程类别和识别器的中间结果，用来在同一界面显出识别过程；置信度仍用短条表示，不写小数。透镜关着时，识别层只留下学员用得上的事实（例如“和上一次相比，回答里的数字从 500 变成 400”），多数位置什么也不显示。评审写进说明开头的“[识别一致]”这类标记一律不当正文显示。

### 2.2 诚实

- **后端做不到的，不在界面上假装。**
  - 前端规则生成的提醒和反馈，标“规则”或“规则示意”。
  - 演示用的样例，标“示例”。
  - 后端本地模式的回复，标“本地模式”。模型没接入的部分只在两处说：工作台顶栏一个模型状态标识（“模型：本地模式／部分接入／已接入”，点开逐项写哪部分等模型、现在用什么代替），以及条目旁一个灰色虚线小圈（读屏名“等待模型接入”，悬停一句说明）。条目上不再重复写“等待模型接入”这几个字，具体说明放进各自的详情（展开原文、成立条件与依据、模型建议的展开部分）。
  - 后端还没有英文版的内容，标 “Chinese source”。
- **分清两种保存状态。** “存在本机”和“已交给后端”，在界面上要看得出区别。
- **未知就说未知。** 证据不足，就显示为灰色的“还不知道”，不往好或坏的方向猜。

### 2.3 一种颜色只表达一种意思

| 颜色 | 意思 |
|---|---|
| 黑（墨色） | 你，以及你能做的事；你的 Agent 也用这个颜色 |
| 琥珀 | 外面变了，或者已经过期 |
| 绿 | 站得住：已完成、已满足、已批准、可用 |
| 红 | 超出了限制 |
| 灰 | 还不知道 |

**人物各有一个固定色相，只用在头像和标识上：** Grace（经理）紫、Chen（业务负责人）洋红、Daniel（技术负责人）青、知识助手蓝。三位同事中英界面同名；称呼时只写名字（“问 Grace”“Chen 回复了你”），列出同事时写“名字（角色）”（英文 “Grace (manager)”），标题处名字旁小字写角色；名字只从 `apps/web/src/app/people.js` 取。资料原文里的称呼（如“陈敏”“经理”）按原文显示。中文里名字与汉字之间留一个空格。

**不用颜色表达的信息：**
- 优先级用柱形，3、2、1 格分别是先做、随后、暂放。
- 进展用圆形：空心是待处理，半圆是正在做，打勾是已处理。

**想加一个新颜色之前，先回答两个问题：** 它表达的是哪一类意思？现有的五类能不能表达？两个都答不上来，就不加。

### 2.4 用户随时知道自己在哪、从哪来、发生了什么

- **返回按层级走。** 事项、资料、测试台都回到工作板；工程师的报告屏回到签字台，签字台回到产品经理工作板；只有在工作板上，才是“离开”。
- **每个动作都有落点。** 提示条只负责提醒，真正的记录要能在别处找到：
  - 这件事的目录；
  - 动态；
  - Agent 标签的“它做了什么”。
- **撤销跟着页面走。** 离开页面，撤销就收回。

### 2.5 字越少越好

- **能用位置、形状、头像说明的，就不写字。**
- **提示最多一句话。** 解释性的内容集中放到“关于”里。
- **文案要求：** 动词开头、口语、具体。按钮写清点了会发生什么，前后用同一个词：按钮叫“交付”，完成后就说“已交付”。
- **同事的话写成人话。** 规则生成的提醒也要像同事会说的话。

### 2.6 双语、深色、手机、无障碍是底线

- **文案中英成对写。** 一律写成 `T('中文', 'English')`。默认跟随系统语言，可以手动切换。
- **中英排版不同。** 中文不加字距；英文标题收紧字距。
- **五种情况都要看过：** 浅色、深色、桌面、390px 手机宽度、键盘操作。不能有横向滚动，也不能有被挤成竖排的文字。
- **焦点和动效：**
  - 焦点要看得见；
  - 遵守系统的“减少动态效果”设置；
  - 拖动操作要有键盘替代（看板支持 ⌥ + 方向键）。

## 3. 现在的做法

下面的参数取自 `apps/web/src/app/styles.css`（颜色、字体、动效变量）和 `apps/web/src/app/material.css`（形状、表面、世界光）。改动时以这两个文件为准。

### 3.1 色板

| 用途 | 变量 | 浅色 | 深色 |
|---|---|---|---|
| 桌面（画布） | `--canvas` | `#e6eae7`（矿物灰绿） | `#0e1211`（带青的石墨） |
| 仪器面（面板、工具栏、右栏） | `--surface` / `--surface-2` | `#f1f3f1` / `#e8ebe9` | `#151a18` / `#1c2220` |
| 槽位（看板列） | `--surface-3` | `#dce1dd` | `#090c0b` |
| 纸面 | `--paper` | `#ffffff` | `#1c2220` |
| 墨色 | `--ink` | `#111715` | `#e8edea` |
| 次级文字 | `--ink-2` / `--ink-3` / `--ink-4` | `#434c49` / `#5a6461` / `#8a938f` | `#b1bab6` / `#8d9692` / `#5c6561` |
| 细线 | `--line` / `--line-2` | `rgba(17, 23, 21, 0.09)` / `0.15` | 白 7.5% / 13% |
| 变了／过期 | `--warn` | `#96500a`（为过 4.5:1 加深） | `#e7a15a` |
| 站得住 | `--good` | `#1b7149` | `#5bc28e` |
| 超限 | `--bad` | `#b3372a` | `#ee7a6a` |
| Grace（经理） | `--p-manager` | `#6550d0` | `#a08fff` |
| Chen（业务负责人） | `--p-business` | `#ad3f88` | `#ea7fc6` |
| Daniel（技术负责人） | `--p-technical` | `#0e7e70` | `#3cc2ae` |
| 知识助手 | 标识渐变 | `#4c6bff → #2bb7d1` | 同左 |
| 我的 Agent | 标识渐变 | `#4a5451 → #111715` | `#7d8885 → #343b39` |
| 世界光 | `--light-warn` / `--light-good` | 琥珀 22% / 绿 24% | 琥珀 16% / 绿 16% |

- **明度台阶：** 槽位 < 桌面 < 仪器面 < 纸。仪器面不描边、不投影，只比桌面亮一档；纸是唯一浮起来的东西。
- **世界光：** 桌面平时没有光（`--amb-*` 为透明）。工作板上出现世界事件时，桌面顶上 560px 内透出琥珀光；这次练习已交付时换成绿光。光只淡入一次，不动。做法在 `apps/web/src/app/material.css`。
- **状态色的用法：** 一律用浅底配深字（例如 `--warn-tint` 底配 `--warn` 字），不用大面积的饱和色块。

### 3.2 字体

- **界面字体：** Instrument Sans（可变宽度与字重），中文回落苹方。字体文件随应用打包（`@fontsource-variable/instrument-sans`，SIL OFL 1.1），演示不联网也能用。正文 14px，行高 1.5。数字用等宽数字（tabular-nums）。
- **读数：** 条件读数的数字用 Instrument Sans 78% 窄体，44px（手机 34px），字重 500；单位用 13px 正文字跟在旁边。知识助手面板的读数是 14px 粗体，名称 11.5px 在上。
- **标题：** 字重 600，字号分档如下：

  | 档 | 字号 | 英文字距 |
  |---|---|---|
  | 首屏 display | 52px（中文 48px） | -0.03em |
  | 大标题 | 36px | -0.02em |
  | 页面标题 | 26px | -0.015em |
  | 区块标题 | 17px | — |

  中文标题一律不加负字距。
- **衬线字（Newsreader，随应用打包，SIL OFL 1.1；中文回落到宋体）：** 只用在“来自世界的文字”上：
  - 资料正文：17px，行高 1.7；
  - 资料标题；
  - 经理委托的引语；
  - 交付稿；
  - 变化情境里的引语。

  分工是：**衬线是世界里的人和文件在说话，无衬线是工具在说话。** 不要拿衬线做装饰。
- **行宽：** 长文不超过 72 个字符宽（72ch）。

### 3.3 形状与层次

- **圆角：** 纸 3px（`--r-paper`），按键 8px（`--r-key`），仪器面和看板列 12px（`--r-panel`）。胶囊形只留给状态标签。其余小件沿用 6 / 9 / 12 / 16 / 22px 五档。
- **层次：** 靠明度台阶和细线分层，不靠卡片。阴影只有三档：
  - `--shadow-paper`：纸面，0.5px 纸边加一道真实的纸影；
  - `--shadow-card`：仪器面上的小件，只有 0.5px 边和 1px 落影；
  - `--shadow-float`：悬浮层和悬停状态。

  区域之间用细线分开。形状和表面都集中写在 `apps/web/src/app/material.css`，颜色仍在 `styles.css` 的变量里。
- **物件感：** 工作里本来就有的东西，可以做成物件：
  - 纸：资料、作品编辑器、交付稿；
  - 便签：同事的旁注；
  - 印章：已提交；
  - 仪器读数：委托旁的四个条件，名称在上、窄体大号数字在下，获批改变时显示原值；知识助手的配置也读成一排读数。

  已经撤回的做法：情境封面图。它好看，但不表达任何信息。

### 3.4 布局

- **整体：** 顶部工具栏 56px，右栏 368px。宽度不够时，右栏收成抽屉。
- **工作板，从上到下：**
  1. 委托与条件（经理的委托下一句交付方向，见 3.6“委托里的方向”）；
  2. 世界事件；
  3. 知识助手；
  4. 事项看板；
  5. 资料。
- **事项工作台：** 左边目录，中间对象，底部动作条。
- **宽度断点：** 1279、1100、860、720px。到手机宽度时，横向排列的元素折行，不压缩正文。

### 3.5 动效

只在两种时候动：回应用户的操作，或者表现世界里的变化。现有的动效：

- **进入工作区：** 只编排这一次。三件起始事项从入口页移到看板上的位置，随后其余卡片和同事依次落下。
- **页面切换：** 用 View Transitions；重排看板卡片时用位置补间（FLIP）。
- **资料与多作品入口（2026-10-05，024/025）：** 资料卡与原文档之间使用可反向的共享纸面转场；两份及以上作品的事项增加紧凑文件夹，点击飞出可读横向纸卡，再次点击回收。文件夹封面保留 React Bits 几何，重叠小纸张已按用户本轮反馈改为横排。沿用纸面、玻璃、字体及颜色语义；完整实现参数、许可与动态证据见[专项验收](../../apps/web/tests/motion-acceptance.md)。
- **世界事件：** 事件出现时，顶边的琥珀线从左往右画一次（520ms，`--ease-out` 即 `cubic-bezier(.23, 1, .32, 1)`），世界光同时淡入；减少动态效果时直接显示。
- **小反馈：**
  - 交付时盖章（见 3.6“交付盖章”）；
  - 同事“正在输入”时，头像外圈呼吸；
  - 获批的条件亮一下。

动效参数：

| 项 | 取值 |
|---|---|
| 主曲线 | 弹簧曲线 `--spring`，用 `linear()` 定义 |
| 备用曲线 | `cubic-bezier(.32, .72, 0, 1)` |
| 时长 | 160 / 280 / 520ms 三档 |
| 普通提示停留 | 3.2 秒 |
| 可撤销提示停留 | 6.5 秒 |

用户开启“减少动态效果”时，跳过这些动效，直接显示结果。

### 3.6 组件

| 组件 | 要点 |
|---|---|
| 条件读数 | 工作板委托旁的四个条件是仪器读数：直接放在桌面上，顶部一根细线，名称在上，窄体大号数字在下，单位跟在数字旁（中文“第 7 天”的“第”“天”同样是单位）。获批改变时数字转绿、顶线加粗为绿，写出原值；获批那一刻亮一下。委托弹层、情境卡里的紧凑条件仍是小格子，条件被外部改变时用琥珀色 |
| 世界事件 | 不装进框：顶边一道 2px 琥珀线，底边一根淡琥珀细线，文字落在被照亮的桌面上。标题下面一句写变化本身，取自新版政策正文的第一句，加上从旧版对出的原值（“原为 500元”）；新旧两版都用只读的资料查询取，不记阅读。后果只在确实有影响时才写：索引落后，或有早于这次更新的测试。三个动作：看哪里变了（琥珀按键）、记为事项、知道了 |

| 补练 | 补练；列表标签“补练” | Optional practice；tag “Practice round” | 反馈后的补练区、我的练习列表 |
| 工程师的主屏 | 签字台 | Sign-off desk | 工程师卡、交给工程之后的落点，报告屏的返回键 |
| 签字 | 签字提交复核；只能由你签 | Sign and submit for review；Only you can sign | 签字单唯一主键与签字线 |
| 交给工程 | 交给工程（n 条） | Hand to engineering；Hand over n tests | 测试台工具区与弹层 |
| 再修一轮 | 再修一轮 | Fix it again | 复核报告屏 |
| 复现／试跑 | 复现这个问题；试跑这组设置 | Reproduce the problem；Run a trial with these | 签字台 |

## 4. 留白

下面这些方向是刻意没有定死的。去探索时，仍然要守住第 2 节的原则。

- **新岗位的物件：** 工程师岗位可以有自己的工作物件，例如终端、代码差异、测试报告，长相不必照搬产品经理的工作台。但颜色的含义、诚实标注、返回方式不变。
- **环境光与情境：** v3 试过让每个情境有自己的颜色，因为看不出含义而撤回。如果以后能找到真正表达含义的做法，可以再试，比如用光线表示“临近上线”。
- **空状态与插图：** 现在的空状态很朴素。可以做得更好，但必须是这个工作世界里的东西，不放泛用插画。
- **数据的呈现：** 测试结果对比、版本差异、评审结论，还有更好的可视化空间。图表同样遵守“一种颜色一个意思”。
- **时间感：** 可以在叙事上出现“第几天”，但不做真实倒计时。
- **更多质感：** 声音、触感，以及更细的物件细节（纸张、便签、印章），都可以试。标准是：去掉它，用户会觉得少了点什么；加上它，用户不会被打扰。

## 5. 为什么是现在这样

这些都是用户评审后做出的修正（2026-10-05，最后一行是 2026-10-24），留作判断依据：

| 之前的问题 | 现在的做法 |
|---|---|
| 灰白单调 | 用纸面、衬线、人物色和物件感加温度，不加装饰色 |
| 情境封面蓝、橙、绿好看，但看不出含义 | 删除；条件改用写着名字的数字 |
| 接手任务后只有一组磁贴，没有工作台 | 改为工作板加事项工作台两层 |
| 橙色、蓝色一色多义 | 一种颜色只表达一种意思；优先级和进展改用形状 |
| 点左上角岗位名直接退回首页 | 返回按层级走 |
| 反馈、测试、Agent 的产出不知道去了哪里 | 右栏四个标签加动态；Agent 标签显示它做了什么 |
| 灰白卡片墙：每块内容都是同一种圆角白卡（2026-10-24） | 「仪器与纸」：桌面是仪器，世界送来的是纸；层次靠明度台阶和细线，只有纸浮起来；环境光只在世界状态变化时出现 |

## 6. 自检

改完界面后，问自己这几个问题：

1. 这个颜色表达的是哪一类意思？
2. 删掉这行字，用户还看得懂吗？
3. 这个变化在世界里留下痕迹了吗？用户回头能找到吗？
4. 这件事后端真的做得到吗？做不到的话，标出来了吗？
5. 它像一个真实的同事或工具会做的事吗？
6. 中英文、深色模式、手机宽度、键盘操作都看过了吗？
