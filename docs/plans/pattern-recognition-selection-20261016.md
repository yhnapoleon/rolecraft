# 模式识别组件选型：补哪些、怎么补

日期：2026-10-16　基于：`origin/main` 319c2a9　目的：在 10-31 前把 RoleCraft 做成一个"理想条件下能端到端展示的模式识别系统"。稳定性、可验证性、安全性不在考虑范围。

配套：[v3 设计文档](../superpowers/specs/2026-10-16-rolecraft-pattern-recognition-redesign.md)（任务定义、数据生成矩阵、加强包细节、课件对照）。本文只做决定：选哪些、按什么顺序、各自怎么接进现有代码。

## 1. 评分标准

每个候选按三项打 1–5 分：

- **技术适配**：接进现有 main 要动多少东西。5 = 槽位和界面已经留好，只差模型；1 = 要改契约、改数据模型、加页面。
- **sexy 与提分**：演示时有没有一个"当场看到识别发生"的时刻；评审会不会因此觉得这是一个识别系统而不是一个 CRUD 应用；报告里能不能出一张有说服力的表或图。
- **课程适配**：对应课程四项要求（监督/无监督、ML/DL、混合/集成、智能感知）中的哪几项，以及三门课课件里有没有直接对应的方法（有的话答辩时评审一眼能对上）。

决定规则：三项合计 ≥ 12 必做；9–11 做报告版，产品接入看余量；≤ 8 不做。

## 3. 选定后的系统是什么

按 ISSM 的 sense-making 流水线讲：原始数据 → 特征 → 识别实体 → 语义关系 → 上下文关系 → 知识。RoleCraft 里对应五个识别器加一个 LLM 组件：

| 识别器 | 输入 | 输出 | 在哪个环节出场 |
|---|---|---|---|
| 证据检索器（C2） | 学员一句话 + 全部可见材料单元 | top-k 相关单元 | 写方案、提交 |
| 关系判定器（C1） | 一句话 + 一个单元 | 支持 / 矛盾 / 无关 + 置信 | 提交反馈，逐句标色 |
| 拒识决策器（C6） | 各类后验 + 代价矩阵 | 判定 / 送人工 | 反馈汇总 |
| 范围检测器（C4） | 用户问题 + 知识库 | 域内 / 域外 + 分数 | 知识助手测试 |
| 行为识别器（C5） | 会话事件序列 | 策略、阶段、异常 | 复盘页"你的行为模式" |
| 语义评审（JUDGE，LLM） | 评分项 + 证据包 | 规则界内的标签 | 提交反馈 |

课程四项要求的对应：监督（C1、C3、C5 策略分类）；无监督（C5 的 HMM、C8 聚类）；ML/DL（C3 经典模型、C1 微调 Transformer、C5 的 LSTM 对照）；混合/集成（C3 集成、C7 融合、C6 决策、规则界 + 模型）；智能感知/意义建构（C4 异常检测、C5 的 DTW 与序列异常、整体流水线框架）。四项全有。

## 4. 怎么补（必做项的实施细则）

### C1 关系判定编码器

**底座与结构。** `FacebookAI/xlm-roberta-base`（main 的加载器按它写的，双语），结构 `pair_aggregate`：每对 (断言, 单元) 输出支持/矛盾/无关三类，按 main 已定的规则聚合（矛盾优先，支持须胜过无关，阈值 τ ≥ 0.5）。`max_tokens=512`，mean pooling。

**训练环境。** Colab 免费 T4，一轮一万句对几分钟。导出时必须在 CPU、torch 2.8.0 / transformers 4.57.1 / safetensors 0.6.2 下跑 `docs/data/return-v3/reference/export_hf_return.py export` 和 `predict`（main 用同一规则加载），这一步在本机 `uv sync --extra encoder` 的环境里做。冻结底部 8 层、学习率 2e-5、batch 16、3 轮、按 dev 的 joint 早停。

**数据。** 中英各约 2,000 条断言、8,000 句对，三个来源合并：
1. **真实作品句**：用脚本策略通过 HTTP API 跑约 40 条会话（这批会话同时是 C5 的轨迹数据），`python -m career_lab.datasets.v3 export --live ... --relation-units` 导出每份作品的每一句，候选为同包材料单元。
2. **生成矩阵**：v3 文档 3.3 节的"标签 × 现象"矩阵（直述、改写、否定、数值比较、数字写法、旧版本、申请当批准、无依据推断、槽位错配），中英各写，四种文风轮换；每条配 1 个金标单元和 3 个难负例（旧版本、数字同槽位异、同话题无关）。
3. **英文**：场景材料 main 已有英文版；断言由 DeepSeek 按同一规格用英文生成，不翻译中文。

标签：生成规格给出；第二遍模型盲判（只给句对，不给规格）一致才保留；程序核对数值与版本。main 的 `datasets/v3/labeling.py` 两遍机制可直接用。分区按事实根 60/20/20；test 不碰。

**接入。** 按 `encoder-return.md` 的目录导出，`registry_cli register --scope external_candidate`，worker 的环境变量按 HANDOVER "没有负责方产物时怎样演示模型建议"那一节的方式指向真实登记。反馈页的逐句建议、引用回跳、覆盖率三类计数 main 都有，不用改前端。

**报告。** 分语言的 Macro-F1、逐类 P/R、混淆矩阵、证据 F1、joint；与 C3 基线同表；线性适配 vs 冻结底层 vs 全量三组（C9）。

**工作量。** 数据 3 天（含 C5 共用的会话），训练与导出 2 天。

### C2 证据切块与检索

**切块。** 改 `src/career_lab/evidence/v2/assembler.py` 构造候选的两处（约 255 行与 336 行）：材料按标题、条目、句号切成单元，每个单元保留 `(material_id, version, char_span)`，`valid_from/until` 沿材料版本。配置、登记册、测试记录按程序转写成单句（"提交时配置：试点人数 20 人……"）。

**检索。** 在 `models/v3/consumer.py` 的逐句推理前加一步：对每句断言，从本包全部单元里取 top-5。三种方法做对照：现有中文二元组 BM25（英文要补英文分词）、`intfloat/multilingual-e5-small`（118M，MIT，中英都行）余弦相似度、两者 RRF。指标 Recall@1/3/5、MRR，金标单元来自 C1 数据。选定的方法写死进产品。

**为什么必须。** main 实测引用整篇材料时每句 529–578 token 全弃权；切块后 pm_pilot 约 60 个单元，24 句 × 60 对在 CPU 上要两分多钟，top-5 后约 15 秒。

**工作量。** 1.5 天。

### C3 经典基线与集成

同一份 C1 数据，特征用 main 的 `rolecraft-linear-text-v1` 文本（TF-IDF 字符 n-gram），模型：朴素贝叶斯（拉普拉斯修正）、kNN（k 用网格）、决策树（增益率，剪枝）、SVM（RBF）、逻辑回归、字符 MLP。集成：LR 的 bagging、决策树的 AdaBoost、随机森林（OOB 误差、置换重要性）、LR + 编码器堆叠、概率融合（alpha 网格）。全部 sklearn，CPU，半天跑完。报告出一张总表，再附偏差—方差的说明（为什么 v2 融合 alpha 选 0：两个模型误差高度相关）。

线性回传（TF-IDF + LR 带证据头）按 `linear-return.md` 导出并登记，作为 C1 的融合分量。

### C4 范围外问题检测

**位置。** `src/career_lab/assistant/service.py` 第 100 行附近：现在 `fallback = not hits or policy_manual`，改为 `fallback = ood_score > τ or policy_manual`。测试结果里新增 `scope_score`、`scope_decision`，前端测试结果卡显示"范围判定：域内 0.12 / 转人工"。

**方法。** 向量用 multilingual-e5-small；域内分布用知识库全部单元加约 100 条域内改写问题拟合高斯（均值 + 收缩协方差），马氏距离为分数；阈值在 dev 上按 TPR 95% 选。`scope_filter` 工作项决定政策单元是否进域内集合，同一个问题在不同配置下判定不同，这正是场景想教的。对照组按 ISSM D3 四法：到 K-Means 簇中心距离、余弦相似度均值 ± kσ、朴素贝叶斯域内似然、句向量自编码器重建误差；再加 one-class SVM、Isolation Forest。

**数据。** 中英各 300 条：域内直述、域内改写（口语、省略、错别字）、域外（远域如天气股票，近域如"报修单到哪一步""上季度差旅总额"）各约 100，LLM 按清单生成，程序核对域内问题确实有答案单元。

**报告。** AUROC、TPR 95% 时 FPR、近域子集单独报告、PCA 二维投影图（PSUPR 得分图的用法）。

**工作量。** 1 天。

### C5 行为轨迹识别

**符号表。** 从时间线事件和对话记录映射，约 14 个符号：`read:{brief|technical|business|faq|policy|approval}`、`ask:{supervisor|tech_lead|business_lead}`（C11 做了再细分为 `ask:tech_lead:capacity` 等）、`configure`、`test:{normal|policy|oos}`（用 C4 判 oos、是否命中政策单元判 policy）、`request:{capacity|resources}`、`approved:*`、`refresh_index`、`event:policy_updated`、`submit`。执行者（人 / 自带 Agent / 参考 Agent）作为序列的一个属性，main 的委托记录能区分。

**数据。** 自己写一个走 HTTP API 的脚本运行器（不用 main 的 `reference_agent`，它用了 `fcntl`，Windows 跑不了）：8 种策略（规范 A 小范围先行、规范 B 申请资源后延期、只读不测、测了不改、申请当批准、乱序、极简、重复提交），每种 40 次，随机化顺序、问题和数值，共约 320 条，标签来自策略。另外组员每人实玩 3 次，再让 Claude Code 经 MCP 玩 3 次，这十几条只作测试并做"人 vs Agent"对比。

**模型。**
- 策略识别：序列编辑距离 / DTW + 1-NN 为主；对照 n-gram 频率 + 随机森林、小 LSTM（PRMLS 的 makeSteps 分段）。
- 阶段推断：`hmmlearn` 的离散 HMM，状态数按 BIC 选 3–5 个，发射分布解释成"探索 / 测试 / 决策 / 调整"。
- 异常：规则列出的四种（政策更新后未测就提交、没读技术材料就申请资源、申请当批准直接配 50 人、重复提交同一配置），用在合理轨迹上训练的 HMM 对数似然作分数，对照一类 SVM 和 Isolation Forest（n-gram 特征）。
- 无监督发现：DTW 距离矩阵 + 层次聚类（Ward，树状图，轮廓系数），看聚出来的簇和策略标签的 ARI。

**接入。** 后端加 `GET /sessions/{id}/behavior`，返回符号序列、HMM 阶段标注、最近参考路径与偏差（缺了什么、多了什么、顺序哪里反了）、异常分与触发规则。前端在 `apps/web/src/features/` 下加一页 `behavior-native`：时间线上色块表示阶段，下面是参考路径对齐图和异常列表。这是唯一要新加的前端页面。

**报告。** 策略识别准确率与混淆矩阵、BIC 曲线与各状态发射分布图、异常 AUROC、真实轨迹（人与 Agent）上的结果单独报告、簇与策略的 ARI。

**工作量。** 数据 1.5 天（与 C1 共用会话）、建模 2 天、接口与页面 2 天。

### C6 拒识决策（半产品半报告）

在 `consumer.py` 聚合出断言级后验后，按代价矩阵（误扣分 3、错误放行 1、送人工 0.5，组内可改）算期望代价，取最小者；低于规则界的照旧。反馈页"待核验"的文案不变，只是决定方式变了。报告出误差—拒识曲线和固定拒识率下的误扣分率；温度缩放的校准前后 ECE。半天。

## 6. 演示里的五个识别时刻

1. 测知识助手："住宿报销上限"答了旧版本 → 系统标 stale；再问"火星天气"→ 范围检测当场转人工，显示分数（C4）。
2. 写方案时写"安排 50 人"，提交后那句标红，引用的是技术材料里"最多 30 名"那一句，不是整篇（C1 + C2）。
3. 反馈页：规则已定标 N 项、模型建议 K 项、待核验 P 项；点开一条待核验，看到它是因为期望代价高于送人工才拒识的（C6）。
4. "你的行为模式"页：阶段色块、最接近"规范 B"但缺了政策更新后的测试、异常分（C5）。
5. 识别实验室：C3 总表、C1 分语言结果、C4 的 ROC 与投影图、C5 的混淆矩阵与 HMM 状态图。

## 7. 识别在流程里够不够、显不显眼

按学员走的九个环节数：读简报与材料（无）、问同事（C10）、配置与审批（确定性规则，不该加）、测知识助手（C4）、写方案（C1 进交付前预演卡）、提交反馈（C2、C1、C6）、复盘（C5）、补练（无）。做完选型后五个环节有识别器，而且每次会话 100% 经过 C4、C1、C5。对比课程例子（皮肤癌检测整个系统就是一个识别器），数量不少。

真正的风险是**不显眼**：远端产品很大，识别器的输出只是反馈卡里几行字，评审会把它看成"带 AI 功能的培训系统"。对策四条，都进本期范围：

1. **叙事顺序反过来**：视频、slides、报告先讲五个识别器和流水线图，再讲它们嵌在哪个业务场景里。
2. **界面上给识别器署名**：每个识别结果旁带模型名和数字。测试卡"范围检测 · 马氏距离 3.2 / 阈值 2.8 · 转人工"；反馈页每句"关系判定 xlm-r-pair-v1 · 矛盾 0.91"；行为页"最近参考路径 规范 B · DTW 距离 4"；对话回复下"依据核查：2 句有依据，1 句无依据"。
3. **识别实验室页**：一条断言从检索、判定到拒识的全部中间结果，加 C3–C5 的图表，专给评审看。
4. **C10 提为必做**：角色回合结束后用 C1 对回复逐句核查（候选为该角色可见的事实单元），无依据的句子标出；同时检查回复是否支持了该角色不可见的事实（泄露）。这样学员主要动作（问、测、写、交、看）每一步都有识别器出手。

C10 的接入点：`src/career_lab/runtime/loop.py`（或 main 上对应的 v2 角色回合实现）回合落库之后、返回之前，追加一个 `reply_check` 字段；前端在回复气泡下显示。

## 8. 与远端协作的说明

共同开发者，直接在 main 上开分支改。会碰到契约指纹内的文件（`assembler.py` 不在指纹内；`consumer.py` 在 `models/**` 内，改后已登记的模型要重新登记一次，两条命令）。不跑回归门禁，不做契约重导出；需要时在 PR 说明里写一句"契约未重导出，演示版"。
