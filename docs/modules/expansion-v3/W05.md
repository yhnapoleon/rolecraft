## 评价什么、在哪个时点评价

`ReviewEvaluator`逐个读取确切作品版本的可信形成时点，再取得该时点的规则快照；同一请求中的不同版本分别评价。请求时间只记录为requested_at，不替代作品时间。形成时点未知时返回待核验，不补造历史。当前状态检查没有自动执行，返回current_state_assessment=null。正式提交现有独立SubmissionEvaluator按提交as_of与确切配置引用处理，见r9接线段；真实业务规则端口仍待公共工厂接入。

上线成功条件遵守用途门槛：

| 作品用途 | 当前处理 |
|---|---|
| 探索、备选、计划、测试计划 | 不要求已经开放或完成测试；可显示调查事实与明确历史声明核验 |
| 正式承诺，明确launch/launch_narrow | 按已冻结规则核容量、资源、期限与验证要求 |
| 正式承诺，no_go/defer | 不套人数大于0、已测试、正数上线日期等成功条件；历史事项另核 |
| 正式承诺，决定未知 | 上线项待核验，不默认launch |
| 结果报告 | 核具体实际行动和明确完成声明，不因purpose或launch标签假定已上线 |
| 用途未知 | 当前作品责任待澄清；仍可显示已核实事实 |

`ResponsibilityFact`是可并存的有类型集合：actual_action、commitment、completion_claim、unknown。每条有criterion、确切scope、来源、发生/有效时点及状态。一个criterion可同时存在承诺、撤回和实际行为；没有记录不等于证明无责任。

历史责任在独立的historical_responsibilities部分呈现。每条finding的sources按完整规范引用去重，保留不同版本、有效窗口和必要quote/span；不跨finding或活动记录合并，不把重复活动次数抹掉。实际行动只用actual_*结构化事实，不把计划配置当作真实消耗；0人和0占用不自动失败。曾承诺或撤回承诺只说明记录存在，不证明已执行，也不据此判当前停止方案错误。明确完成声明与声明时点的完整记录比较；日志不完整就unknown，存在运行记录也不证明覆盖充分。真实超用或不符的完成声明可以追问，但不改成当前停止作品的整体NOT_MET。

责任在作品形成后发生时不纳入原判断；核历史实际数值时，证明还必须在行动/声明发生点成立，后来的政策不能倒扣过去。作品时有效而请求时已失效的记录仍按作品时点处理。开放文本中的模型提取不能直接写入这些可信事实；来源映射由已冻结公共适配层负责。

## 默认无模型的事实反馈

`api.reviews_v2.create_review_evaluator(reader)`是可运行的默认只读工厂，未配置模型也会输出独立verified_facts，与结论质量分开。`handle`可读取正式ReviewInput或保存的ReviewRequest中的decision/followup_of；None保持未知，不强迫改写作品形式。没有显式决定时，只有已绑定同版本/形成点的可信structured_subject声明才可作候选，不从自由文本猜launch。提示分别指出用途未知、已知用途但缺决定、已有用户声明；声明不自动确认审批或执行。决定保持None也可正常查看事实反馈。关联异议只返回linked_not_resolved；followup_evidence_status=not_evaluated，正式反馈提示其中引文默认未核实，后续仍须按实际源版本、原句、时点和支持关系重验。授权可引用、补证链接或对象存在都不等于采信，也不自动解决。

`prepare_review_feedback`在事务外评价已授权、已保存的ReviewRequest，逐确切作品版本准备正式FeedbackV2；`review_feedback_plan`重新核对保存请求hash和主体、生成公共ObjectWrite/Mutation，不建立队列或私有过程表，不合成跨作品总分。真正worker、私有输入carrier和可信生产reader仍待公共端口，不能把只读预览或测试闭包当作生产执行器。

事实摘要包括：

- 仅统计作品该版本明确关联的证据引用：公共适配器须从作品evidence_refs和结构化段内显式证据链接取得declared_refs，不把cycle/task等内部关系或自动上下文当证据引用。来源按session/kind/id/version/config_version去重，引用处按完整引用及quote/span去重。作品正文、额外候选和规则证明不算作品引用。
- 核对原文、确切版本、当前权限、形成时间与有效窗口。统计和摘要分开原文/版本已核对数与参照时点有效数，保留过期来源的历史用途。不可核验引用用提交引用digest及状态持久化，不存受限源身份/标题/原文；引用存在仍不等于支持结论。
- 在作品形成前核材料读取、测试、提问、实际收到回复和向学员展示事件。按确切事件引用去重，逐项核事件类型、时间、执行者与关联目标。
- 只有可信适配器声明完整授权窗口、且没有来源缺口时，零条才显示为零。范围受限、日志缺失或执行者/关联不匹配时标unknown，并保留已核实记录，不能断言没有调查。
- 保留作品author/executor/adopter和活动执行者；Agent调查不算学员独立调查。提问、收到、展示、理解不互推，独立理解仍为unobserved。

局部责任、规则、辅助引用不可见/缺失/不可核验时，仅相应项pending并给安全泛化原因；其他已核验规则与历史继续返回。会话/作品主体无权仍整体拒绝；凭据错误、未知ProtocolError及程序错误继续抛出。隐藏责任不会暴露类型、发生时间、私有scope或来源数量。结果报告缺少可核验typed实际行动/完成声明时明确提示待核验，不推断没有发生。

事实数量不生成MET/NOT_MET、能力分或语义支持标签。有记录的暂缓与完整日志内无记录的放弃，在默认返回中已经不同；是否理由充分仍是advisory/pending。

事实、历史责任与原规则项现写入正式FeedbackV2的verified_facts/historical_responsibilities/rule_items，不只停在sidecar。作品形成点、评审请求点与捕获点分开，父反馈as_of取请求点，子事实as_of取作品点。未知形成点的正式section保留unknown及None计数；旧记录缺字段仍由公共读取原样返回None/未记录，不补零。c9正式历史finding允许occurred_at=None。隐藏条目的安全时点未知时直接保存None与unknown finding，并以section.partial及next_options保留对应项pending，不捏造发生时间。

## 只读来源与权限边界

`SnapshotEvidenceReader`实际读取有预期SHA-256的不可变JSON快照，解析精确版本、形成点、逐记录visible_to、活动及其覆盖范围、Evaluation引用和政策、各对象时点的RuleSnapshot。篡改、重复版本和缺少规则快照均拒绝；缺逐记录受众时不默认公开。这个格式仅是本包内部适配及测试输入，不是新公共schema，也不是另一份世界权威存储。

快照必须由受信任公共层按调用者权限生成，调用前由Gateway重查当前凭据。文件哈希只在内部证明输入没变，不证明授权或事实来源；公开source_snapshot_hash绑定实际授权来源投影，不公开包含隐藏记录的整文件hash，避免通过隐藏/缺失差异推断存在信息。reader额外核session、actor、read能力及显式对象范围，不能独立处理线上凭据吊销。它不会读取角色私有材料来补证，也不从空列表反推完整账本。

文件reader测试在临时目录持久化明确合成记录，调用真实SnapshotEvidenceReader与默认工厂，没有注入脚本质量标签或假supported来证明事实层。r9另有从实际V2Store读取的StoreEvidenceReader及真实API/worker/浏览器证据。W02/W03/W04真实快照生产、正式rubric映射与角色披露来源仍待固定公共输入；本包不读取活动源码或把材料提示句当gold。

## 规则与语义建议

规则事实独立于模型文本预算。长作品和材料可按确切quote/span取材；超预算标text_overflow，保留完整规则事实，不静默截断后称完整。模型输入只含中性候选ID、一次正文与必要时点；模型回citation_ids，服务器映射固定引用。

非点规则区间可交Judge判断，但建议不能改变规则界。用户可见说明保留原区间、规则证据和模型建议；diagnostics保留独立rule_items。草稿契约禁止model_advice.rule_bound，结构化双来源展示还需正式合同。没有冻结权重时不发明总分。

EvidenceSupportVerifier检查具体责任、标签、结论和全部固定正反证据；模型给短原句与理由，由服务器唯一定位跨度。未知ID、伪造或歧义原句、超预算、失败均不能成为supported。支持关系仍是模型建议，不升级为规则或人工真值。

`rubrics/v4/provider.py:create_feedback_engine`可显式配置真实provider。构造不读取隐式密钥或发请求；每项仅1次Judge及最多1次支持核验，任何解析/引用/支持失败不再次调用模型，timeout和完整输入字节预算有界，现有provider输出上限512 tokens。核验器与Judge是否同源必须记录，不能把同源核验称独立校准。本轮没有在线模型调用或费用。

本轮C-W05-02必需项是上述无模型事实反馈。真实模型区分合理性、人工校准列条件检查，按具体费用/人数另获授权；这不豁免最终产品QA的真实模型/Agent门槛。
