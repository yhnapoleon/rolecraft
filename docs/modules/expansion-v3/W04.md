### 原生同事部件接入

独占入口为`apps/web/src/features/roles-native/index.ts`，只操作传入容器内新增的DOM，样式全部限定在`.rc-roles`。没有React入口、全局凭据、自己的HTTP客户端、后台轮询或第二份请求日志；共享app/ui.js、全局样式和挂载由032负责。

```ts
import { mount, type RolesNativeAdapter } from './features/roles-native';
// callbacks由032映射既有client/Gateway；这里的类型是UI投影，不是公共API schema。
const handle = mount(container, callbacks satisfies RolesNativeAdapter);
await handle.refresh(); // 重读当前公开投影；不等于刷新job上下文。
// 工作台离开此插槽时：
handle.destroy();
```

| callback / 投影 | 接线要求 |
|---|---|
| `read()` | 返回固定session的公开RolesView：工作语言、已安装模式、三同事、真实question/reply/status、公开材料title/version及可操作能力。不得传私有审计或从模型措辞猜权限。旧回复保持原文；该接口是现有client到UI的投影。 |
| `send({roleId,text})` | 用现有client提交真实命令；只有原请求接受/登记已确认才resolve。组件不乐观伪造回复、job或材料；发送期间的新编辑不被旧确认覆盖。 |
| `recover()` | 恢复client日志里的原请求，不能换request_id重发新命令；若确认原问已接受，可返回`{confirmed:{roleId,text}}`，组件只清除仍与其一致的旧输入。读取或恢复失败保留输入，错误详情不原样渲染。 |
| `retry(turnId)` / `refreshContext(turnId)` | 映射原job的正式重试/refresh；只有投影明确允许才显示按钮，不自动执行。 |
| `openMaterial({id,title,version})` | 回跳到该公开材料的确切版本。组件只显示title和version，文本经textContent写入，不拼HTML或自行生成链接。 |
| `subscribe(changed)` | 沿用现有client的更新通知；组件收到通知重读，不创建新轮询。destroy取消通知与UI locale监听。 |
| `drafts.read/write` | 可选连接现有client草稿保存。组件仅保留交互中的内存副本；未接草稿持久化时不宣称刷新浏览器能保留未发输入。 |

`mode='local_reference'`明确显示本地资料参考与等待模型接入；`unavailable`保留已有对话并禁发，不能生成模板回复假装已完成。UI locale只改变控件语言，不能更改固定workLanguage或翻译历史；组件拒绝同一挂载中会话/工作语言突然变更。日期、区间和配置名按原文本渲染，公开引用显示材料名和版本。

## 公开回复与私有生成

`RoleReply` 保存学员原问题原文，并承载实际回复、说出原句、身份/执行者、时点和可公开周期关联。除学员自己输入的原问题外，生成字段不含 `prompt_messages`、context/prompt hash、未披露来源、内部 fact ID、模型尝试或完整角色条件。公开披露引用实际 utterance；其内部事实和材料映射只在私有 `RoleContext.actual_disclosures` 中保留。

`PrivateGeneration` 是内存中的生成计划，包含实际 prompt/hash、内部 RoleContext、收到分享的完整引用和文本、scope/provenance、refresh_count 和模型尝试。它不是注册存储模型，不以自建 kind 或替换 DTO 绕过公共保护。`RoleService.generate` 需要 W01 可信私有端口；未提供时在模型调用之前返回 `role_private_storage_unavailable`。原子落库只能由正式端口产生受保护的 RoleContext write，并与公开回复一起提交。私有记录可引用公开回复，公开回复不反向依赖私有记录。

c6/c7 公共层已封住已知 r1 私有形态的新写入，以及学员/Agent 对历史记录的 read、历史版本读、view、引用、请求恢复、重放、job 结果和导出。旧记录在隔离测试库直接作为历史行置入，不经 execute 触发新写入守卫；每次断言前确认危险行和原内容真实存在，断言后核对原数据未改。另用真实 execute 验证新写拒绝，并保留安全新回复可读的正向对照。旧 strict xfail 已替换为有效通道断言。

角色本人和研究审计仍可读取原件；其他角色、学员和受限 Agent 均不能读到内部 prompt。`parse_public_reply` 对角色本人取到的旧私有形态仍明确拒绝，后续安全接续方案见下节。`legacy_r1_fixture.py` 仅提供旧数据结构，不在生产工厂注册为替代 DTO。Observation/tools 尚未安装，不把503作为它们的隐私证明。

## 来源、连续记忆与委托范围

`ScenarioKnowledge.from_package` 消费 W02 真正核过 hash 的材料。版本按角色实际收到的记录选择：初始激活版本与该角色收到的合法事件构成可知范围。全局更新不会让未收到通知的角色忘记旧版，也不授予未来版本。事件只携原来源引用，重新经过角色权限和 never/paraphrase 下限；不能靠 public 事件文本降低披露限制。

`RoleMemory` 保存原对话引用和完整来源 ID/kind/version/时点；`ReceivedShare` 保存 share 与 product 的精确引用、收到时点及实际正文。旧版与新版不会依赖模型复述才能留下：三轮使用不复述附件的受控模型，第二轮及第三轮仍能取得此前收到的 v1/v2 正文。私有持久化端口尚缺，因此目前这是源数据与生成计划的验收，不能冒充已部署的三轮恢复体验。

内部 prompt 中的记忆携带 `kind:object@version`、观察/有效时点、当时 share/product 和来源引用。未授权学员材料及其派生记忆连同这些标识一起省略，公开回复不暴露私有追溯元数据。

`ContextSnapshot.generation_sources` 按类别处理权限：角色自身获准材料和不含学员对象摘录的角色知识不套 caller 白名单；学员作品/附件及其派生对话按实际 learner refs 核 scope。受限内容保留在角色内部记忆中，在该次生成明确省略；模型和公开结果得到省略数量，不暴露被省略对象的身份或内容。这样既保留同事的知识，也阻断借同事读取未授权作品的路径。

新读取检查当前 share 修订、接收角色、精确 product 版本以及移除/撤销状态。已撤销/移除的源不重新读；早先真正收到的私有记忆仍按历史来源保留。恢复作品不由本包自动重分享。

## 私有来源标识与立场机械边界（r4后续）

非公开材料身份和正式私有对象引用在服务端保留真实 `kind/object/version`。提示词中的对应追溯信息改为中性别名；`PrivateGeneration.source_aliases` 保存准确映射，公开回复不携带该映射。获准知识本身保留，公共材料和已授权学员作品继续使用准确版本。输出正文、结构化引用/错误内容经过统一标识守卫，裸ID、完整引用、大小写、常见URL/HTML编码和中文紧邻形式都不能回显；拒绝信息不带被拒绝原文。

本轮补独立于W02内容分布的策略测试：把never与不属于actors的role_only材料放进角色known_materials，仍拒绝进入生成；合法role_only受众另有正向对照。`source_binding` 在模型调用和尝试计数之前检查。

私有立场新增 `RoleStanceState`、`StanceProposal`、`StanceResolution`、`StanceChange`，不注册新公开对象、评分API或第二套状态存储。声明的角色关注点作为初始私有状态；后续提案明确目标条目、原revision、拟议文本与确切事实引用。事实收据来自实际可知的账本条目，保存内容指纹、来源版本和获知seq。该指纹排除文档版本号；只重复引用、换版本号而内容未变、用户压力和模型自述理由不构成新事实。

机械处理先核对身份/revision/时点、来源是否确已知，再检查相对既有状态是否有新内容及新的获知时点。没有合格新依据时原状态不变。来源存在但支持改变未确认时提案为pending；模型理由、逐字匹配、prompt约束和单纯引用存在都不能代替支持核验。接受变化还要求服务端安装的规则/独立复核器明确确认语义新意和支持关系，结果绑定旧状态、提案、依据摘要及检查时点。当前没有生产语义复核器；受控测试的支持器仅证明这些机械条件和记录结构，不证明语言判断正确。

变化记录保存旧立场、新立场、促成的具体事实引用、实际获知seq与支持记录。它只影响角色私有立场，不调用审批、配置、资源或业务状态转换。`RoleStanceEvidence` 继续只记实际原句；它不是采纳提案或世界事实证据。私有生成/提案结果固定 `language_consistency=unverified`、`learner_penalty_allowed=false`：模型若自由表述无依据让步，不得据此自动推断学员能力或扣分。

**仍需正式验收：** 自由语言提案识别、语义支持、新事实的语义等价性、模型多轮文字与状态一致性，以及完整私有持久端口。当前默认只能以账本中实际收到的条目形成受控依据；其他工具发现需要可信事实准入。仅业务seq无法分辨同seq内先后时采取保守不变，不冒充已证明新事实。正式角色生成端口未接通前，本轮不宣称可用的多轮立场模拟。

受控 `PrivateGenerationPort` 测试已执行 `RoleService.generate` 的成功、空审计、错误角色和错误受众分支，并用实际V2Store检查原生RoleContext只对相应角色/审计可见、公开回复受众正确且资源不变。该fixture只写一个有界原生审计样例，没有替代实际prompt/立场/attempt的生产载体；P2-1最终门槛仍是032真实私有端口与storage组合全绿。

## 标识与三轴窗口复核（031-r4后续）

私有来源标识检查现将句末标点和来源文件名视为可达引用形态。除真实对象ID，W02已校验的 `material_files` 相对路径与文件名也进入私有标识集合。URL、HTML及Unicode/hex转义按最多4轮规范化检查；每个中间表示均检查。超过检查深度仍残留未完成检查的转义形态时安全拒绝，已到固定点的普通文字不当作编码攻击。正向用例继续允许公共文件名、公开引用和获准共享作品的准确版本。

所有立场时间关系统一使用 `version_point_relation` 的三分量偏序：business_seq、workspace_revision、storage_revision 都满足不晚于才成立。各分量一早一晚是不可比较；未知或未通过类型校验的点为unknown，不能按字典序或只按两个分量猜测。提案须处于旧状态至快照的窗口，支持核验须处于提案至快照的窗口，事实取得须不晚于提案。未知/不可比较不改变旧立场，保持pending；明显未来提案和不合法快照状态拒绝。

`StanceFactReceipt.acquired_at` 保存完整获知点。只有经实际 material_activation=0 建立的初始角色知识使用(0,0,0)；事件事实从可信收件事件的完整 `occurred_at` 取得，不用捕获时点或文档版本号回填。只有seq、缺workspace/storage时保留原seq和 `acquired_at=None`，不能被采纳为已证实的新变化依据。角色端口需提供此完整窗口；这仍是待032接入的私有协议要求，不是本轮修改公共schema。

## 业务立场与旧会话安全接续

业务立场、专业关注点和公开审批理由可以在实际对话中解释。原始角色配置、prompt、隐藏 rubric/gold/probes、未来及 never 内容继续禁止公开。`PrivateGeneration.opinions` 只对回复中实际出现的声明立场留原句，绑定角色配置来源、字段和索引，标注 `role_opinion / verbatim_match_only`；这只证明原句与声明立场有字面对应，不核定语义正确、世界事实、G0 或学员理解。未说出的立场不记入意见记录；已有公开规则仍可按材料来源追溯。

旧 r1 继续使用需要正式私有 snapshot 适配器提供最小投影，当前没有自行挂通：

1. 仅在可信角色身份和固定历史时点读取原件，核对 session、role、原 request/turn 与当时 executor；研究审计可读不等于生成授权。
2. 只选原问题、实际回复、原时点、明确的对话引用作为“历史原话”。不读取/重放整段旧 prompt，不从旧 prompt 回填已收到作品、披露或理解，也不改写旧行。
3. 若原提问存在于 RoleTurn，以其不可变记录追问来源；缺失或冲突明确标记，不能拿当前周期或当前内容补造。
4. 学员对象摘录必须由旧明确引用和可信历史关系恢复权限标签；来源不完整时不把整段旧回复当成角色固有知识。受限 Agent 无权的摘录继续省略并说明，角色自身合法知识保持。
5. 投影属于私有角色记忆计划，由新公开回复另行引用实际原句；不得通过一份宽松公开 DTO 绕过共同守卫，也不创建公开对象反向引用私有历史。
6. 新旧记录共存、撤销/移除、权限变窄、跨周期和错误详情都要有正反验证，且原记录 hash 不变。正式端口及这轮接续验证完成前，旧会话继续生成仍保持 blocked。

该计划交 S02 实施；本轮只是明确安全投影边界，没有把 decode 拒绝改成绕过。

## 固定快照与失败

`ContextPort.capture(view, auth, turn, as_of=...)` 只消费 worker handler 的固定 `TransactionView` 与正式 role snapshot 投影。模块不读实时 `store.view`、不调用私有 SQL、不签发替代 owner/system 身份。合法原提问先通过公共事务与job一起保存；生成缺投影时返回 `role_snapshot_unavailable`，缺私有载体返回 `role_private_storage_unavailable`，问题不会随失败丢失。`head_dependencies` 只列实际读取的 share、产品头和事项；无关事务不会导致此适配器另设全会话栅栏。当前无关写入测试用真实 Gateway/worker 与明确标记的权威投影夹具验证此边界，正式 S02 投影仍未完成。

输出披露拦截/解析不合法分别返回确定性 `role_output_blocked`/`role_model_invalid`，由 c4 worker 一次停止。超时/传输故障以 status=503 的稳定 ProtocolError 保留类别与实际/unknown usage、可取得的 cost，再交公共重试预算；确定性拦截使用422，一次停止。已知带内部 retries 的旧模型适配器被拒绝，避免隐藏多次供应商调用。本模块不创建第二套重试、队列或生命周期。失败尝试的持久审计仍需要正式 W01 sink，纯测试中的列表只用于验证调用参数。

## 申请、还价及静态事件

`ScenarioApprovalPort.from_w02` 使用固定 W02 limits、角色和确定性 evaluate；不另立批准条件。decider 必须在真实 RoleSpec 中拥有 `approve_business`。未知资源键返回稳定错误。每个还价候选和接受动作都通过同一个 evaluate，批准前不改有效资源。

`business_decided` 是固定事件类型，受众由实际角色订阅与 decider 得出；接受和成功资源写入另留事件。`operation()` 和 `action_operation()` 使用静态 `approvals.resolve`/Literal `ActionInput.tool` 注册 projector，真实 request_result/replay 可恢复安全事件数据。

容量批准可能触发 W02 的 `business_scope_requested` 等后续变化。本包要求正式 `decision_followup` 端口组合 W02 原计划；缺失时返回 `role_decision_followup_unavailable`，整笔资源提交回滚。测试中关闭此要求的对象明确是事务边界夹具。真实 W02 场景与后续事件组合仍待重新绑定，不能据事务夹具称 AC06/07 完整通过。
