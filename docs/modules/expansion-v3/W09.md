# Reference Agent: authorized execution

The reference executor uses a server-issued credential and the same learner projection,
Operation/Mutation transaction core, capabilities, object scopes and action scopes as the
normal workspace. A client-supplied executor never grants access. Research credentials
remain excluded from public tools. Delegation issuance and adoption remain human-only.

## Public entry points

`python -m career_lab.reference_agent validate --manifest <run.json>` checks the current
protocol. `python -m career_lab.reference_agent run --help` lists the fixed checklist
entry: immutable registry IDs, an explicit credential file and a read-only local database
bind the run to the server identity. `--resume` queries the original request/job; it never
redispatches an uncertain action. English and Chinese work languages use the same chain.

`GET /sessions/{id}/tools` and `/observation` now accept authenticated reference executors.
The catalogue remains capability-filtered; metadata is not acquired knowledge. Actual
material reads are returned with exact versions and no hidden fact IDs.

## Verification and remaining seams

The public HTTP tests cover both languages, empty knowledge before acquisition, actual
read receipts, reference attribution and human-only adoption. Existing RUN-01..04
protocol/recovery/identity tests are retained. These checks establish mechanism only.

No identity is rewritten to human and no evidence/projection code is bypassed here.

RUN-05 business-terminal verification, the worker success path and complete prefix

checklist continues to report `business_terminal_verified=false`. Paid models are not

## Ordinary and active tool loops

```sh
python -m career_lab.reference_agent loop --help
python -m career_lab.reference_agent loop --manifest <run.json> --registry <registry-dir> \
  --runtime-id <registration-id> --evaluation-id <registration-id> \
  --database <session.db> --credentials <private-credentials.json> \
  --scenario-root <installed-package> --output <new-run-dir> \
  --strategy active --goal "Check the pilot brief"
```

Use `ordinary` for the direct loop and `active` for an explicit belief context. Both
use the same advertised tools, real HTTP transactions and budget checks. Session,
versions and request IDs are supplied by the runner; function aliases reuse the
existing public function-tool mapping. The next model turn receives actual public
tool results. Internal material fact keys are removed by the existing projection.

The executable model fixture is an immutable Runtime.model JSON file with
`provider: controlled`, a `revision`, and `replies` in ModelReply format. Its usage
receipts are controlled inputs, not measured real-model quality or a paid invoice.
The CLI currently loads this controlled provider only. Real provider configuration,
its fixed revision and budget-aware transport remain an EXT-RUN-MODEL integration
condition; no key discovery or paid call occurs. Runtime prompt files are integrity
checked by the registry; this mechanism runner uses its code-bound public-data
instructions. It does not consume scenario-private role prompts.

Each run records authorized observations, tool results, model attempts, decision
candidates and choices. Candidate `expected_cost` remains an unverified estimate;
actual consumption comes from attempt receipts and typed tool results. Known nested
receipts contribute their tokens, cost and attempt count; unknown nested receipts stop
subsequent calls. Host-controlled receipts verify this accounting mechanism only. Candidate
checks cover advertised availability and the public argument schema. Object
permissions, current versions and business consequences are enforced by the original
server core. Unexecuted proposals are not claimed to be feasible interventions.

The local belief sidecar keeps goal, actual quoted observations, unknowns, hypotheses,
plan, revision, limits and known/unknown consumption. Thoughts bind to actual
observation hashes and never become observed facts automatically. A source-version
change is retained for comparison, including moved text spans; `conflict` here does
not claim a model-verified semantic contradiction. Ordinary-loop prompts do not receive
the explicit belief state.

Recovery validates fixed inputs and budgets. A model call with unknown completion is
not repeated. A durably saved reply is adopted once after restart; a sent business
command is recovered by its original request. Each decision keeps its original
observation point; concurrent workspace changes stop execution instead of silently
rebasing it. An explicit new run/attempt is required after failure. `--resume` reads the
saved terminal result without calling a model. Nested unknown usage stops further
calls; incomplete totals remain null/incomplete, never zero. The attempt count is a
known lower bound while nested usage is unavailable. Potentially model-backed tools
are blocked before dispatch when any allowance is exhausted. Public tools currently
provide no authoritative reservation or upper bound for nested provider consumption;
end-to-end hard caps for real nested providers remain an integration dependency.
This controlled runner does not establish that future providers stay within a reserved
remote budget, and proposal estimates cannot supply that proof.

## Evaluation identity

`--evaluation-id` is the immutable registry record ID. The record pins the evaluation's
logical ID, revision and root FileRef SHA-256; the RunManifest supplies that root FileRef,
and the session supplies its immutable binding. A dependency file cannot substitute
for the selected root manifest. No candidate rubric filename, revision or current hash
is embedded in the runner. A new approved evaluation is supplied as a new registered
input after installation; old runs retain their original identity.

## Input integrity and credential rejection

Runtime and Evaluation inputs bind to registered root manifests, including logical ID,
revision and SHA-256. Package membership alone cannot authorize an evaluation binding.
Request identities include immutable run and action identity. A confirmed
`request_id_reused` conflict remains failed; unknown transport results still query the
original request without redispatch. Recovery verifies the complete normalized command
fingerprint through the existing store's read-only `replay()` API, then matches the
authorized HTTP transaction ID. The local database is opened read-only; no handlers,
approvals or model calls are replayed. This closes interruptions before failure checkpoint
persistence; deployments without a matching local database remain unsupported.

Portable registration shares the existing credential field vocabulary with delegated
response redaction. JSON, YAML, TOML and text are inspected before blob persistence;
Structured values are parsed before inspecting individual strings, keeping distinct fields
separate. URL userinfo is rejected through URL parsing, including IPv6 authorities and
authority punctuation. Credential-free
URLs, relative references and ordinary Markdown remain valid.

Historical REG-05/RUN-03/RUN-04 have verified behavioral green tests but no independently
located original red records. These records are not backfilled or represented as complete
TDD history. RUN-05 and the documented product dependencies remain incomplete.

The reference and external Agent clients share bounded session HTTP transport: a total
request timeout, an 8 MB decoded response limit, no redirects, no proxy-environment
inheritance and no retries. Each caller retains its identity and public-output checks.
Recovery fault tests use the shared transport return boundary; real HTTP and transaction
execution remain unchanged. This line does not modify `issue()`; the integrated credential-security request fingerprint is retained.

## Credential deployment configuration

Credential issuance/recovery and local server/worker startup require
`CAREER_LAB_CREDENTIAL_KEY_ID` and `CAREER_LAB_CREDENTIAL_KEY`. Production has no default
secret. Tests obtain explicitly fictitious keys from the shared test fixture; this does
not provision a deployment key. The registry rejects the secret environment field in
portable packages; the non-secret key identifier can remain in configuration metadata.

The integrated credential regression still expects legitimate reference catalogue reads
to return 403. The authorized reference-read behavior returns 200 while forged credentials
remain rejected. That cross-owner assertion needs alignment before the newest combined
tree can pass its complete gate; no test was skipped or weakened in this line.
