# Reference Agent: authorized execution

The reference executor uses a server-issued credential and the same learner projection,
Operation/Mutation transaction core, capabilities, object scopes and action scopes as the
normal workspace. A client-supplied executor never grants access. Research credentials
remain excluded from public tools. Delegation issuance and adoption remain human-only.

## Public entry points

`python -m career_lab.reference_agent validate --manifest <run.json>` checks the current
protocol. `python -m career_lab.reference_agent run --help` lists the fixed checklist
entry: immutable registry IDs, an explicit credential file and a read-only local database
bind the run to the server identity. `--resume` queries the original request/job; it never
redispatches an uncertain action. English and Chinese work languages use the same chain.

`GET /sessions/{id}/tools` and `/observation` now accept authenticated reference executors.
The catalogue remains capability-filtered; metadata is not acquired knowledge. Actual
material reads are returned with exact versions and no hidden fact IDs.

## Verification and remaining seams

The public HTTP tests cover both languages, empty knowledge before acquisition, actual
read receipts, reference attribution and human-only adoption. Existing RUN-01..04
protocol/recovery/identity tests are retained. These checks establish mechanism only.

Reference feedback is still blocked at `StoreEvidenceReader.__init__`: its separate
identity guard excludes reference executors. The feedback owner must reuse
`delegations.service.require_learner(auth)` there (replace the two-line guard with a
shared check; import it), preserving the authorized query view and evidence windows.
No identity is rewritten to human and no evidence/projection code is bypassed here.

RUN-05 business-terminal verification, the worker success path and complete prefix
recovery remain incomplete until their real dependencies are connected. A completed
checklist continues to report `business_terminal_verified=false`. Paid models are not
called; local fixtures cannot establish model quality. Public wire contracts are unchanged.

## Input integrity and credential rejection

Runtime and Evaluation inputs bind to registered root manifests, including logical ID,
revision and SHA-256. Package membership alone cannot authorize an evaluation binding.
Request identities include immutable run and action identity. A confirmed
`request_id_reused` conflict remains failed; unknown transport results still query the
original request without redispatch.

Portable registration shares the existing credential field vocabulary with delegated
response redaction. JSON, YAML, TOML and text are inspected before blob persistence;
URL userinfo is rejected through URL parsing, including IPv6 authorities. Credential-free
URLs, relative references and ordinary Markdown remain valid.

Historical REG-05/RUN-03/RUN-04 have verified behavioral green tests but no independently
located original red records. These records are not backfilled or represented as complete
TDD history. RUN-05 and the documented product dependencies remain incomplete. Shared
HTTP transport extraction is a separate follow-up; no change is made to `issue()`.
