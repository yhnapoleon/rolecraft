## 已实现行为

[场景包](../../../scenarios/pm_pilot/v2/manifest.json)包含29条带单位、版本、来源片段与披露规则的事实、
13份材料版本、9条FAQ、3项政策的前后版本、需求/用户组/冲突访谈、12条可执行探针及角色资料。
材料均为手工组织的虚构训练设定；生成器用于确定性重建，不宣称来自真实业务或模型生成研究。

用户可用c0先测试。第一次显式应用配置触发一次政策更新，源与索引继续分别保存。
配置会实际影响知识域、范围过滤、日更/实时/人工政策、人工兜底、检索片段大小与数量；
资源不足的实时同步等能力会在effective config中明确未生效。配置中未获支持的工作项不被冒充已完成。
试点人数/日期保留请求值并提示约束冲突，不把试图配置视为业务已上线。

助手按可见知识库片段检索。调查材料不进入知识库。返回原文范围、配置身份、实际覆盖域和可追问的版本信息。
检索使用去除通用问法词后的查询词覆盖率；它是确定性的词面检索，尚未验证普遍语义召回质量。
无命中、范围外、禁止主题、人工核验、新鲜度守卫分别留稳定原因。
自报category/expected被原样保存，不产生gold或评分。

权限投影覆盖材料读取、目录和输出版本字典。转述材料只返回获准摘要，丢弃秘密原文的quote/span；
never材料不可读。场景原件与内部状态只供可信模块使用，不能直接作为客户端响应。

确定性审批策略返回批准或拒绝计划，保留申请与决定；拒绝后可创建修改后的新申请。
只有可信系统supervisor权限能规划资源变化。还价/接受的体验由W04实现，目前返回未安装。
纯状态规划没有写数据库；需要公共事务真正提交后，才构成产品中的已批准资源。

## 模块接口

- `career_lab.scenarios.v2.load_package(root)`：核对manifest、内容哈希、引用、数字与来源、角色定义、资源/成本、需求和用户组总数。
- `ScenarioEngine.initial(session_id)`：创建c0与内部状态初值。
- `ScenarioEngine.plan(snapshot, command, auth, evidence_check=None)`：消费公共Command/AuthContext，返回PlannedTransition。请求body不能自造可信auth。证据存在性/授权由集成方提供解析器；未提供时不会假认任意证据有效。
- `ScenarioEngine.catalog(snapshot, auth)` / `read(snapshot, ref, auth)`：只读权限/版本投影。
- `ScenarioEngine.public_event(event, snapshot, auth)`：过滤事件接收者和材料版本元数据。
- `Assistant(package).run(snapshot, TestRequestV2, auth, request_id, tuning=None)`：真实片段检索，返回TestExecution。
- `effective_config(package, config, resources)` / `evaluate_request(package, request, snapshot, evidence_check)`：确定性配置与审批计算，无存储副作用。

ScenarioSnapshot、PlannedTransition、RetrievalTuning与TestExecution是模块内部实现对象，
不替代公共API/storage schema。snapshot及transition中的原始材料版本向量是世界私有状态。
W01/032需将计划转换为公共Mutation并原子保存；本模块没有另建数据库或公共请求模型。

c0的配置对象revision为1，config_version为0。后续应用同时递增这两个各有含义的版本。
事件序号与storage revision在计划中有明确边界，最终须与公共事务实现核对后验收。

## 可执行命令

从本包独立checkout运行，其venv必须按本工作区锁文件建立：

```sh
env -u PYTHONPATH .venv/bin/python -m career_lab.scenarios.v2 --help
env -u PYTHONPATH .venv/bin/python -m career_lab.scenarios.v2 validate scenarios/pm_pilot/v2
env -u PYTHONPATH .venv/bin/python -m career_lab.scenarios.v2 paths scenarios/pm_pilot/v2
env -u PYTHONPATH .venv/bin/python -m career_lab.scenarios.v2 probes scenarios/pm_pilot/v2
env -u PYTHONPATH .venv/bin/python -m pytest -q tests/expansion_v3/w02
```

命令输出JSON，校验/探针失败返回非零。paths与probes是内部场景作者工具；
它们显式构造测试身份来核对同一策略和助手，不包含真实token解析、持久化或HTTP/worker。
已执行四条路径和未登记的35人、45人容量、动态域人工核验组合，运行结果绑定场景hash。
路径ID没有进入引擎成功条件。每条probe的期望属于私有作者夹具，普通自由测试不能读取它。

## r2：031首轮审阅修复

W02-R1：所有全会话变更（配置应用及自动事件、全量刷新、申请/审批、暂停/恢复）要求
allowed_objects=None；有限对象授权不自动覆盖全会话，即使列出了pilot和部分材料也拒绝。
受限调用仍可读取获准材料。助手测试需要read与act，且必须明确能读取pilot配置；
例如仅faq会拒绝，faq+pilot可以测试，返回的来源/索引/片段仍只限获准材料。
完整配置的返回依赖已授予的pilot读取权，不因获准配置而扩大材料权限。

public_event改收完整AuthContext，核对会话、读取权、过期、角色与对象范围；
过滤后的版本向量没有任何获准变化时不返回事件，也不透出其他材料名称。
有限对象授权不展示没有定义对象投影的会话申请/决定/生命周期事件。
ScenarioSnapshot/PlannedTransition始终是可信事务内部对象，禁止直接序列化给客户端。

W02-R2：分别以目标人数、工作项成本、目标日期核对容量/人日/期限的真实缺口。
混合申请包含无必要增量时整项拒绝，可改为只申请确有缺口的条款；不暗中部分批准。
引用证据可选，存在时仍核验。自然语言“需要更多资源”本身不产生资源缺口。

本地已支持先申请再配置：request_business可使用现有ActionInput.config携带待实施配置，
或默认以当前配置为依据。请求创建时将确切依据固定到内部request_targets，保存basis_hash，
此时不会应用配置、触发政策更新或更改资源。批准后的配置仍须用户显式应用。
之后修改当前方案不会改写旧请求的依据；恢复时丢失该依据明确失败，不能改用当前方案。
正式BusinessRequest尚需可持久化、可回读的依据绑定字段，已列W02-S05交032；
这不表示公共API已经支持该输入，也不把提议版本当成已经生效的配置对象。

W02-R3：freshness_guard显式验证none/warn/fallback三态，默认none，布尔及非法值拒绝。
同一source=2/index=1状态下，none返回旧来源原文且不加警告，warn附警告，fallback拦下转人工；
三者均保留真实来源/索引版本。没有人工兜底时被守卫拦下的结果仍明确为无法完成。
正式字段落地后保持同一语义，不再使用bool替代。

r1的源码归档、回执、原始运行日志均保留原字节；r2使用新的delivery及证据目录。
