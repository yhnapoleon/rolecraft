当前场景版本为2.2.0，目标是支持用户调查、比较、申请、测试与修订。已有23份材料版本、
50条带来源事实及12条真实模块运行的公开问答记录。材料时长目标为20–30分钟，
尚未经过真人计时或完整产品实操验证。

本包消费登记指定的W01 r3固定输入。其后已发现新的公共层问题并进入返工，
因此这里的同步API验证不等于W01最终质量已通过，也不等于整套产品完成。

## 场景内容与行为

- 支持台样本区分咨询数量、处理时长与等待、重复标记和未覆盖口径；
  人群、访谈与三角色立场存在可追问的冲突。
- 差旅住宿从500调整到400；餐补100和请假流程保持稳定，入职知识独立成域。
- 第一次显式应用方案触发政策更新；第一次有效资源请求带来演示提前通知；
  容量获批后业务方追加范围意向。通知不自动应用新配置或采纳新范围。
- 阅读和测试不会单凭次数推动业务变化。私人作品的实际保存路径仍由W03负责组合验证。
- 角色有不同职责、目标、可接受条件和事件订阅。role_knowledge消费known_facts和披露规则，
  以服务器角色身份及实际获知版本构建材料视图；默认初始窗口，不自动读取未来版本。
  这不代替W04的连续记忆、对话模型和实际披露记录。
- 原始私有内容不进入学员材料；合法摘要去除原始quote/span。角色自己的权限与提问者权限分别处理。
- 历史材料可按确切版本读取；密码重置流程与索取实际密码分开。边界说明属于工作区资料，
  不进入助手知识库，即使scope_filter关闭也不将其当普通知识答案。

原r2失败清单与隐藏probe重合的缺陷已先行隔离。新公开记录来自public_cases.py的实际执行，
保留问题、回答、配置、引用和版本，不包含预期标签。其准确输入包和原始结果在本次回执证据中。
旧已曝光探针只作训练/回归参考，不能重新声称未见。私有probe与公开材料的完整提问重合会使loader拒绝；
public-probes命令实际只导出public=true子集。

## 正式契约与存储接入

ScenarioModule提供注册工厂，通过原有ExtensionRegistry安装场景及以下冻结槽位，
不删除路由、不挂第二套router、不直接访问数据库私有方法：

- actions：配置、索引刷新、资料读取与业务申请。
- approvals.resolve：复用实际确定性策略，公共Mutation原子保存请求/决定并应用资源。
- tests.create / tests.list：真实执行、不可变结果与恢复。
- materials.list：授权目录；目录可见不等于学员已获得内容。

ScenarioStateV2保存源、索引、激活记录和当前配置引用；PlannedTransition转换为公共Mutation，
业务seq/workspace/storage版本由W01提交层决定。BusinessRequest使用正式BusinessBasis，
提议配置不冒充已应用配置。TestResultV2带execution/config_ref、实际时间/执行者、chunk、源与索引版本。
min_score、三态freshness_guard、manual_domains使用公共AssistantConfig；不能通过未入库的调参偷偷覆盖配置版本。

审批必要性和保障前提写入规则与学员材料。引用可选；合法user_groups等材料引用可参与真实审批。
决定给出可理解的拒绝原因，获批不会自动应用配置。原“policy”域名作为policy_travel的兼容别名，
实际检索与覆盖按规范化知识域记录。

baseline.json和manifest对象均按AssistantConfig解析后比较规范化字段；
原始文件hash仍验证，未知字段仍拒绝。契约默认字段增加不会要求跳过清单验证。

149项相称测试通过：102项W02（含9项正式Gateway/SQLite API检查）与47项v1回归；
13条作者探针和5条模块路径运行通过，获批路径实际带材料引用。
已进行真实本机HTTP：创建、c0、重放、配置、过期索引测试、带证据申请、审批生效与历史来源读取成功。

仍有两个具体公共端口缺口：

1. W01 r3的外部引用resolver只有auth/ref/VersionPoint/SessionBindings，缺当前权威ScenarioStateV2。
   模块不能仅凭seq或引用自报valid_from确认政策v2已激活；注册resolver对此明确返回reference_context_required。
   自身handler内的精确状态检查已实现，刷新后的v2引用持久化仍失败并完整回滚，不计作重测通过。
2. 资料read action可以成功，但引用只在result/command而不在对象write时，公共层未记录其外部锚点；
   GET requests/{id}复取该读取回执返回404。不能通过伪造对象类型或旁路SQL补救。

这两项及生产装配交031/032处理。W03/W04/W05/W06、前端和完整人用闭环仍须组合验收，
不会用模块命令、构造身份或测试替身冒充真实产品QA。所有新交付按本地commit及Claude握手登记。

## 运行

在本包工作区使用自己的venv和全新数据库：

```sh
env -u PYTHONPATH .venv/bin/python -m career_lab.scenarios.v2 validate scenarios/pm_pilot/v2
env -u PYTHONPATH .venv/bin/python -m career_lab.scenarios.v2 probes scenarios/pm_pilot/v2
env -u PYTHONPATH .venv/bin/python -m career_lab.scenarios.v2 public-probes scenarios/pm_pilot/v2
env -u PYTHONPATH .venv/bin/python -m career_lab.scenarios.v2 paths scenarios/pm_pilot/v2
env -u PYTHONPATH .venv/bin/python -m career_lab.scenarios.v2 serve scenarios/pm_pilot/v2 \
  --database-url sqlite:///runs/local/w02-new-session.db --port 19832
```

serve只监听127.0.0.1，使用冻结Gateway，未启动时没有常驻服务。它是后端验证入口，
未将新场景自动部署或替换稳定前端。原始日志、来源、HTTP记录、旧交付保护及源码身份见完成回执。
