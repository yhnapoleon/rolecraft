## 单一权威存储与正式入口

生产入口是 `api.workspace_v2.install_workspace_operations(registry, roles=...)`，在现有 `create_app(..., extensions=registry)` 的Gateway槽位安装W03纯处理函数。`workspace.extension.workspace_plan`将域计划转换为正式ObjectWrite/Mutation；不直接访问V2Store私有方法，不删除或替换冻结HTTP路由。

`storage/workspace_v2.py`只转出W01公开计划类型，不创建表、事务、幂等账本或版本时钟。旧私有SQLite/router实现已从生产路径撤出，仅作为明确命名的历史测试替身保留在tests目录；其通过结果不代替Gateway/V2Store验收。

已安装的正式槽位：

- `work_items.create / update / batch / list`
- `work_products.create / versions.create / versions.list / list / adopt`
- `work_products.shares.create / shares.change`

采用使用ProductAdopt；新命令显式携带schema_version=2。TaskBatch按一个事务合并创建/更新计划，保留原事项和版本引用。读端暂使用正式V2Response作为明确的页容器；公共transport须按此已知结构解析，不能随意猜测嵌套形状。

## 已有域行为与兼容

事项可新增、排序、暂放、阻塞、拆分为子事项、通过relations合并处理、可恢复移除。仅对本次新增/变更的父项或关系做存活检查；移除父事项不会阻止原子事项或其作品继续编辑。新增链接仍不能指向已移除事项，已有历史引用不被删除。

作品使用不可变版本，kind与purpose分开；未知用途文字仍保存。测试行/调查模块版本、来源return_id、采用者与执行者分别保留。正式TestCase保留intent/refs，调查支持test_compare及独立review_focus，不能把“核对索引”误映射为支持/矛盾。

分享固定确切版本和接收角色，新版本不自动分享。学员及完整工作区授权的Agent读取作品页时，items按当前share头投影该确切版本的visibility/shares，页级shares给出这些作品各版本的完整ProductShare头（接收角色、product.version、id/version、revoked_at），供刷新后撤销；读投影不写回不可变作品。v1已分享而v2未分享时，v2仍为private，页级分享记录明确指向v1。客户端refresh/loadShares优先读取该投影，不依赖尚未冻结的GET shares。

移除作品在同一Mutation内撤销全部有效分享，workspace/storage各只递增一次；恢复作品不恢复分享，必须明确重新分享。原版本、旧share版本、已保存回复/披露/提交历史保持原样，不能用历史记忆重新取得源读取权限。正式角色源读取走公共V2Store.read_shared_product；domain里的旧角色读取分支仅服务历史夹具。

受限对象scope的公共view可能不含全部share。当前不扩大权限：读取返回sharing_complete=false并不把未知状态报为private；客户端明确提示授权不足。此scope下移除先以share_scope_incomplete拒绝，避免半撤销或静默漏撤销。完整受限Agent体验依赖032提供受信任的完整分享投影/原子级联，仍列公共接线限制。角色上下文通过公共授权服务接入。create_under_tasks采用正式显式授权，不能仅因某task ID在作用域内就扩大创建权限。工作区纯函数只消费公共层已过滤的对象视图/授权回调，不另造权限算法。

导入先显式选择和preview，保留原浏览器副本、正文、草稿、原始结构和确实存在的历史。缺失版本通过ImportConflict/ImportVersionMap标明，不能补造。旧测试不自动变成新会话的运行记录；没有确切服务端引用时，保留原始链接并标未核验。原请求恢复不执行存档中的pending操作。

## 前端接现有v4

生产feature入口导出WorkspaceClient、迁移准备函数和 `native-slots.ts` 的小型DOM绑定；它们复用现有v4导航、`app/i18n.ts`的T()及--warn/--bad等样式变量。032在共享文件接入现有事项/作品/导入槽位。WorkspacePanel及browser-recovery页面只作为恢复测试夹具，不是第二个生产工作台，不从production index导出。

本地journal写入在原生Web Lock内读取最新记录并按对象合并，网络请求有独立会话锁。草稿保存固定base、writer、token和谱系；refresh不默默升级head。pending创建在同一锁内核对正文/base/token，ACK只能清理实际提交版本。明确拒绝退出pending但保留输入；未知结果继续使用原键。旧错误pending与旧无base存档均保留，不能由新head补造历史。

冲突可显式合并、另存或放弃当前草稿；放弃需要核对当前token，且不能丢弃结果未知请求的草稿。存在草稿时不能直接移除作品。读取列表遇到事务交错可有界重读，写入不会自动更换版本重放。
