# RoleCraft 工作区前端

**2026-10-05 工作台 v4 + Agent UI 第一、二阶段。** 主入口是一个连接现有 RoleCraft API 的工作台，界面支持中文和英文。

**页面顺序：** 岗位选择（`#/`）→ AI 产品经理入口（`#/pm`）→ 工作板（`#/work`）→ 事项工作台（`#/task/<id>`）、资料（`#/doc/<id>`）、测试台（`#/bench`）→ 上线评审（`#/review`）。返回按层级走：工作板上是“离开”，其余页面是“工作板”。

**工作板：** 经理委托与四个条件、世界事件横幅、知识助手条、事项看板（先做 / 随后 / 暂放，可拖动）、资料卡。

**事项工作台：** 头部（优先级、进展、说明）、左侧目录（这件事的作品、资料、测试）、中间对象（开始页、作品编辑器、资料、测试台）、动作条（引用依据、测一测、问同事、交给我的 Agent、请求评审）。

**右栏四个标签：** 讨论（同事提醒、三位同事、我的 Agent、对话）、反馈（记录核对与观察）、Agent（交出去、带回来、它做了什么）、动态（按时间排列的全部变化）。在事项里可切换“这件事 / 整件工作”。

**数据来源：**
- 后端提供：会话、资料、同事回复、配置与审批、助手测试、交付、评审、证据和过程记录。断线时不会切换成模拟答案。
- 只在浏览器保存：事项与进展、作品版本、作品引用的依据、对话所属的事项、Agent 任务包和回传。交付时，用户自己选择把哪些作品合并进后端六字段交付稿的“方案、作品与依据”。
- 前端规则生成、界面标“规则”的内容：同事提醒、三位同事的排序建议、请求评审后的记录核对与观察、评审页的“情境反馈”。规则在 `src/app/coach.js`。

**本工作区的后端基线尚未提供：** 开放作品同步、跨回合角色记忆、同事主动发言、提交后关联修订、语言参数和 MCP。需要后端补的接口见 [前端接口需求与未实现功能](../../docs/design/frontend-interface-requirements.md)。独立的第一批前后端接口改造未接入本工作区，不能把两个预览的能力合并计算。

## Agent UI 第一阶段

可执行测试作品与[第二阶段调查视图](#agent-ui-第二阶段情境化调查视图)在 v4 基础上实现；完整探索顺序见[Agent UI 计划](../../docs/plans/agent-ui-exploration-plan.md)，第三阶段仍为后续计划。

**如何体验：** 在事项中打开右侧 Agent，复制任务包给 Codex 等外部 Agent。任务包已包含可选测试作品的格式与限制；Agent 可以返回普通文字或 `test_set`。粘贴或上传返回内容，预览后导入为待检查作品，再采用。逐条展开可以编辑问题、验证目的和预期；运行调用真实 API，结果与问题版本绑定，可重测、查看历史、记观察及引用为依据。

**本轮预览：** <http://127.0.0.1:18510/>，连接独立本机 API `18502`；数据库与原服务分离。原 8510 预览不含本轮改动。重启本轮前端时使用 `ROLECRAFT_API_TARGET=http://127.0.0.1:18502 npm run dev -- --port 18510`；API/worker 的通用启动方式见下方，使用独立端口与同一个验收数据库。

**已实现：**
- `schemaVersion: 1`、`returnId`、可选 `requestId`、`artifact.kind: test_set`、`cases`；格式/来源/规模检查、重复回传与冲突检查、普通 Markdown 兼容。最多 20 行，问题 4,000 字符，目的/预期各 2,000 字符。
- 应用生成稳定行 ID；行/作品修订、结构草稿、可读正文摘要、增删与撤销；结构字段不会在导入或保存时丢失。
- 逐行显式运行；运行前持久化 `pending.localRun`，确认后写 `testRunMeta`；原请求重试、刷新恢复及重复点击边界。暂停/提交后测试作品只读。
- 运行结果与“问题和预期”切换；历史结果、实际来源和版本、观察、引用。执行完成不自动获得通过结论。
- 与 v4 共用字体、纸面、状态色和动效；结果展开约 180ms，键盘触发不做位移动画，尊重减弱动效；长标题目录和 390px 窄屏无横向溢出。

**实现位置：** `src/app/test-set-view.js`、`test-set.css` 为视图；`ui.js` 为工作流与草稿；`public/workbench-engine.js` 为结构/版本/导入；`types.ts`、`store.ts`、`workbench-live.ts` 为真实运行与恢复。共享引擎的旧 `/demo/` 行为仍跑回归。

**验证（2026-10-05）：**
- `ROLECRAFT_TEST_API=http://127.0.0.1:18502 npm test`：33 项通过，包含 4 项真实 HTTP/worker 测试；另有 51 项作品/状态行为回归通过。
- `npm run build`、`git diff --check` 通过。
- 实际浏览器：任务包→当前 Codex 根据可见任务简报生成计划→预览→导入→采用→设置→逐行执行；编辑后直接点重测、Tab 转焦、旧结果提示、引用、观察、增删撤销、刷新留存、中英文和 1440px/390px 走查。
- 现场停止本轮 API 后运行、刷新，再重启并恢复原请求，结果回到原行；服务端已完成但响应丢失、本地持久化失败、同题不同测试行等另由自动测试覆盖。

## 普通导入作品的管理

2026-10-05 用户体验后先要求补齐基础作品操作，随后明确要求操作更紧凑、直觉，并继续 Agent UI 第二阶段。普通 Markdown 导入后即可以编辑，不需要先采用；采用只决定是否纳入当前正式作品集合。

- 作品顶部采用编辑/预览、保存、删除图标按钮，保留无障碍名称；鼠标悬停或键盘聚焦显示说明，Escape 可收起提示。编辑和自动草稿保留原机制，明确保存会形成内容版本。普通文字、测试计划与调查共用保存和删除操作。
- 删除只将工作台副本标为 `removedAt`，不修改电脑原文件。左侧“已移除作品”可恢复；正文、草稿、采用状态、ID、引用、历史运行与已有提交快照保留。
- 已移除作品不进入新的导出、交付汇总与待检查数量，也不能继续编辑/运行。移除最新修订不会把旧版本自动重新当成当前作品；重复回传会指向恢复，不自动重新导入。
- 自动生成且尚未手改的交付汇总会随移除重新计算；手写交付文本保留并提示核对，仍可按当前选择重写或清空依据。已保存/提交的交付版本不撤回。
- 暂停/已提交练习不能新增导入、移除或恢复；存储失败不把作品假装移除成功。

基础作品管理修复时的验证：36 项前端测试含 4 项真实 HTTP/worker、57 项本地状态回归、生产构建与差异检查通过。独立浏览器存档实际验证 MD 导入后未采用编辑保存、预览、删除、刷新、恢复内容和版本；另验证删除后纯自动交付草稿不残留旧正文。删除与恢复只在合成验收作品上测试。只读代码复核覆盖手写交付文本保留与提示，不代表真人体验研究。本轮图标操作与第二阶段的最新自动验证见下节。

## Agent UI 第二阶段：情境化调查视图

**2026-10-05：限定实现、自动验证与独立 IAB 的真实外部 Agent 闭环已通过。** 用户已明确恢复第二阶段，取代前一轮暂停安排。本阶段继续用外部 Agent 手动回传，没有接入内部生成模型、MCP 或任意 HTML/JavaScript 执行。

**如何使用：** 根据现有政策测试和反馈打开标为“规则起始视图”的调查，或把当前问题、选择的作品与实际记录交给自己的 Agent。任务包包含调查格式；Agent 可以选择普通文字、测试计划或调查作品，并自主选择调查模块及顺序。回传预览并导入后，待检查阶段即可读取真实证据、核对来源版本；采用后才允许重测、引用和重排。原第一阶段流程继续保留。

**回传结构：** 沿用 `schemaVersion: 1`、`returnId`、可选 `requestId`；新增 `artifact.kind: investigation`、标题、用途“探索笔记”、最多 1,000 字符的 `question`，以及 1–8 个模块：

| 模块 | 回传内容 | 界面实际行为 |
|---|---|---|
| `note` | 可选标题、分析文字 | 标明 Agent 分析或规则整理，保留判断的不确定性 |
| `test_compare` | 1–4 个不重复的真实测试 ID | 显示实际回答、引用及版本，不能用回传文字冒充运行 |
| `source_check` | 真实测试 ID、目标材料 ID 与版本 | 核对回答实际引用与明确选择的资料版本；目标版本可以不同，材料 ID 必须确实被该测试引用 |
| `retest` | 真实测试 ID、可选标签 | 采用并显式操作后，同题重新执行，旧记录保留，新结果追加到调查 |

**数据与权限：**
- 模块 ID 由应用分配；内容和排序进入作品版本，正文摘要从结构派生。非法结构、外部模块 ID、伪造结果、脚本或无关引用被拒绝；新版 `kind: text` 和旧 Markdown/JSON 回传均兼容。
- 有任务包标识时，引用须在该包选择的真实测试与材料版本范围内；测试还须存在于本会话，材料 ID 当前可读。无包回传只使用当前可见的实际记录。
- `source_check` 按确切版本读取原文；历史内容无法取得时显示缺失，不用当前正文替代。导出历史材料正文只使用本会话已经成功读取的对应版本缓存。
- 重测使用独立的调查、模块和基准测试元数据，执行前随原请求持久化，成功或重试成功后统一投影。只读、未采用、已移除或版本不匹配的调查不能运行。
- 规则起始调查保留 `ruleOrigin` 标记。模块来自 Agent 选择不等于模型评审可靠，也不自动给出“通过”结论。

**实现位置：** `src/app/investigation-view.js`、`investigation.css` 负责视图；`ui.js` 负责入口、作品图标操作与交互；`public/workbench-engine.js` 负责结构、版本、引用范围和导入；`workbench-live.ts`、`types.ts`、`store.ts` 负责确切来源读取、重测归属与恢复。

**最新自动验证：** 最终复跑 `ROLECRAFT_TEST_API=http://127.0.0.1:18502 npm test`，42 项 Vitest（含 4 项真实 HTTP/worker）及 67 项引擎状态回归全部通过；TypeScript/Vite 构建和 `git diff --check` 通过。覆盖非法引用、模块顺序与历史、来源版本、调查重测归属、原请求恢复及调查关联统计等边界。“关联测试”表示有实际记录，不表示结论已验证。

**实际浏览器证据：**

- 在 18510 的独立 IAB 测试会话中，从三模块规则起始调查导出[实际任务包](tests/fixtures/investigation-browser-task-package.json)；Codex 根据包生成[四模块回传](tests/fixtures/investigation-codex-return.json)，顺序为 `source_check → note → test_compare → retest`，与规则起始视图不同。
- 预览→导入待检查→采用→上下重排至 v3→实际重测→刷新恢复通过。待检查时重测和引用禁用；刷新后仍保留 v3、模块顺序及三条关联测试记录。
- `source_check` 分别取得旧引用 policy v1 的 500 和所选 policy v2 的 400 原文。未刷新索引时重测仍引用 v1；这条结果如实保留，没有自动判为“已验证”。
- 图标编辑/预览/保存、键盘聚焦说明通过；1440×1000 桌面和中英文 390×844 没有横向溢出，控制台无错误。截图：[桌面调查与关联记录](tests/screenshots/agent-ui-investigation-desktop.png)、[中文手机](tests/screenshots/agent-ui-investigation-mobile.png)、[英文手机](tests/screenshots/agent-ui-investigation-mobile-en.png)、[图标工具栏与焦点提示](tests/screenshots/work-icon-toolbar.png)。
- 所有回传和截图均来自本次合成验收会话，不是用户真实作品。用户已确认本轮体验；一次成功链路不代表模型稳定性或学习收益已被验证。

**边界：** 仍使用 v4 基线后端与本地检索/抽取知识助手，没有接入独立后端批次、内置生成 Agent、MCP、完整情境化 Judge 或第三阶段。本轮不包含部署；未验证真人收益或稳定的模型生成效果。

## 颜色

每种颜色只表示一类意思：黑是你和你能做的事（你的 Agent 同色）；琥珀是外面变了或已过期；绿是站得住（完成、满足、批准、可用）；红是超出限制；灰是还不知道。人物用固定色相：Priya 紫、Mei 洋红、Daniel 青、知识助手蓝。优先级用柱形（3、2、1 格），进展用圆形（空、半、勾）。界面里“⋯ → 关于这个工作台”有同样的说明。

## 界面语言

- **默认语言：** 跟随系统，`navigator.languages` 中第一个中文或英文；两者都不是时用英文。
- **手动切换：** 每页右上角的地球图标可以切换，选择记在 `rolecraft.locale` 中，取值为 `auto`、`zh` 或 `en`。系统语言变化时，“跟随系统”会同步更新。
- **翻译范围：** 界面文字、事项起始标题、作品用途、资料标题、评审条目名和已知错误都会翻译。
- **不翻译的内容：** 资料正文、同事回复、助手回答和评审理由来自后端，目前只有中文；英文界面下原样显示，资料、同事回复和助手回答标 “Chinese source”。`local` 模式的同事回复另标“本地模式”。

## 启动

需要 Node.js >= 22.12、npm，以及按仓库 `uv.lock` 安装的 Python 环境。在仓库根目录完成 `uv sync --locked`，分别启动 API 与 worker；两个进程必须使用同一数据库：

```sh
uv run career-lab serve --host 127.0.0.1 --port 8502 --database-url sqlite:////tmp/rolecraft-web-preview.db --provider local
```

```sh
uv run career-lab worker --database-url sqlite:////tmp/rolecraft-web-preview.db --provider local
```

启动前端：

```sh
cd apps/web
npm ci
npm run build
npm run preview -- --port 8510
```

打开 <http://127.0.0.1:8510/>。开发使用 `npm run dev`，地址为 <http://127.0.0.1:5173/>。Vite 开发与预览将 `/api/*` 转发至 `http://127.0.0.1:8502/*`，可用 `ROLECRAFT_API_TARGET` 指定其他 API 地址。正式托管仍需配置同源 `/api` 转发。

`local` 是后端抽取模式，不调用外部大模型。API 与 worker 的 provider、数据库配置需一致；前端不接收模型密钥。真实模型按仓库已有 CLI 配置，本轮没有新增外部模型调用。

## 三个入口与存档

| 地址 | 当前用途 | 状态来源 |
|---|---|---|
| `/` | 工作台 v4，产品主入口 | `rolecraft.live.workspace.v1` 保存会话凭据与请求日志；`rolecraft.open-work.ui.v1` 保存事项、作品和本地时间记录；`rolecraft.locale` 保存界面语言 |
| `/connected/` | 保留的原 React API 连接页 | 与新主入口使用同一 API 会话存档，可读取相同服务端状态 |
| `/demo/` | 冻结的离线规则演示，仍加载 `public/workbench.js` 和 `public/workbench.css`，不再随主入口更新 | `practice.open-work.v2`，与连接版隔离，不作为网络失败时的后备结果 |

旧高仿真演示的浏览器存档保留在 `/demo/`，不会自动转换成服务端记录。存档按域名、端口隔离；不同地址的记录不会自动迁移。没有账户登录、跨设备同步或服务端会话列表。不要分享 `rolecraft.live.workspace.v1`：其中包含 bearer token。任务包和本地笔记导出均不包含会话 token。

## 接口覆盖

以下涵盖现有后端全部 16 个 HTTP 操作，其中 15 个已在本机成功调用。可选的辅助判断只验证了未配置时的 503 分支；主入口不显示这个实验入口，`/connected/` 仍保留。页面里的场景条件来自现有后端，提前上线变体为第 **5** 天；离线原型保留自己的第 3 天设定。

| 操作 | 新界面入口与适配 | 本轮证据 |
|---|---|---|
| `GET /health` | 顶部连接状态、运行模式、刷新 | 浏览器与真实 HTTP |
| `POST /sessions` | 选岗后接手工作；主场景、提前上线、15 人容量 | 三个场景创建成功；存储异常时阻止创建 |
| `GET /sessions/{id}` | 恢复会话、刷新、每次业务动作后的权威状态 | 刷新恢复、冲突后同步 |
| `GET .../materials` | 资料页、测试来源、按 `as_of_seq` 查看历史 | 当前与历史材料、角色私有资料隔离 |
| `POST .../actions` | 阅读、试点设置、扩容/资源申请、索引刷新、暂停/恢复。阅读会计入政策更新的触发次数，同一资料的同一版本只发一次 | 七种动作均覆盖；同一个原请求重试不重复生效 |
| `POST .../approvals/resolve` | 申请面板的明确审核动作 | 扩容至 60 人；资源至 6 人日和第 10 天；申请本身不批准 |
| `POST .../tests` | 助手测试、同题重测 | 旧索引答案 500，刷新后 400；保留配置、源与索引版本 |
| `POST .../turns` | 右栏“讨论”；本地记录每条消息所属的事项 | 三角色真实 worker 回复、实际 `model_revision` |
| `GET .../jobs/{id}` | 排队状态、轮询、刷新恢复 | worker 停止时保持 queued，重启后完成原任务 |
| `POST .../artifacts` | 交付面板保存六字段成果；作品合并到 `rationale` | 最新编辑内容、字段映射、成果版本 |
| `POST .../submissions` | 保存之后固定提交 | 文字/配置变化需重新保存；提交后权威状态只读 |
| `POST .../feedback` | 固定提交后创建反馈任务 | 真实 worker 生成 `rules-v2` 反馈 |
| `GET .../feedback/{submission}` | 读取已保存反馈、恢复旧练习 | 与 worker 返回结果一致 |
| `GET .../timeline` | 反馈页的后端过程记录 | 只读取历史，不重新调用模型 |
| `GET .../evidence/{submission}/{criterion}/{evidence}` | 每条反馈中的证据按钮 | 集成测试遍历所有返回证据，时点不晚于提交 |
| `POST .../relation-checks` | 辅助证据判断（实验）；仅 `/connected/` 有入口 | 当前未配置冻结实验，503 明确显示且不阻塞其他工作；成功推断未验证 |

所有会话接口携带 `Authorization: Bearer`。读取已暂停或已提交会话的材料不会尝试追加业务阅读事件；新操作仍由后端权限与状态约束控制。后端现有 rubric 的不足和待人工核验结果原样呈现，不能把抽取回复或规则反馈称为完整情境化 Judge。

## 恢复与数据边界

- 写入前先持久化原请求。超时、断线、5xx 留下待确认请求，恢复时重发相同 ID 与内容；不因刷新或点击自动另造请求。
- 409 明确拒绝后刷新权威状态，保留草稿，要求重新检查；不偷偷改变 `expected_version` 再发。
- 会话创建没有幂等键，失败时不自动重复；先验证浏览器可保存，避免在已知存储故障下创建无法恢复的会话。
- 角色与反馈使用独立 worker。排队时保留 job ID，刷新只查询；终态失败如实显示。反馈失败重跑受现有后端接口限制。
- 配置保存与审批分开。可保存超过当前资源的申请方案，但保存不代表已经获批；原型的自动批准、定时假回复和本地政策触发在连接版被禁止。
- 自由作品仍保存在本地。正式交付先核对六字段并保存，再固定提交；刚编辑就交付时会同步保存最新正文。已固定版本不可由页面“修订”解锁。
- Agent 任务包只导出实际可见且已打开的后端材料和选择的本地作品/测试；引用正文取实际结果，不能由回传作品伪造。
- **评审证据包上限：** 后端评审把全部资料、配置、交付稿和测试拼成一个证据包，超过 16,000 字节会整份降级为“证据不足”。交付面板让用户选择附上的作品，并在估算接近上限时提醒。这只是缓解，根本修复见接口需求 P0-5。
- **时间：** 后端没有时间戳。对话和动态里的时间，是这个页面看到它发生的时间；页面加载前就存在的记录不显示时间。

## 验证与复现

在 `apps/web` 运行普通回归与生产构建：

```sh
npm test
npm run build
```

启动 API、worker 和前端预览后，可执行真实 HTTP 集成测试。使用专门的验证数据库；测试创建新会话，不清空已有记录：

```sh
ROLECRAFT_TEST_API=http://127.0.0.1:8510/api npm test
```

浏览器走查脚本在 `tests/walkthrough/`：`walk.mjs` 跑完整经历，`walk-flows.mjs` 跑申请审批、Agent 带回、新建事项。需要设置 `CHROME_BIN`（Chrome 或 chrome-headless-shell），可选 `BASE`（默认 `http://127.0.0.1:8510/`）和 `OUT`（截图目录）：

```sh
CHROME_BIN=/path/to/chrome node tests/walkthrough/walk.mjs 1440 900 zh
```

`src/workbench-live.test.ts` 的 4 项真实 HTTP 集成测试在没有 `ROLECRAFT_TEST_API` 时跳过。其余测试随普通命令执行。仓库根的后端检查：

```sh
uv run pytest -q
uv run pytest apps/web/tests/test_existing_backend.py -q
```
